# 9.4.b — The legacy route answers 301 / 302 / 410 / 404 from the `redirects` rows

**Task / Status:** 9.4.b done (9.4.c not touched). Branch `w/9.4b`, three commits, not merged or pushed.

## What was built

- **Collection** (`engine/packages/cms/src/collections/redirects/index.ts`): `'410'` added to `REDIRECT_CODE_LABELS`
  (`Gone (410)` / `Hilang (410)`); `to` is no longer `required` and gets `validateTo`: required unless `code` is
  `'410'`, and empty when it is. `payload-types.ts` regenerated with the generator (`to?: string | null`,
  `code: '301' | '302' | '410'`).
- **Loader** (`engine/packages/http/src/legacy/redirect-map.ts`, `payload-redirects.ts`): `readRedirectMap(reader, site)`
  pages through every row of one site (pages of 1,000, `sort: 'id'` so paging is stable), `select: { from, to, code }`,
  `overrideAccess: true` with the why in a comment, codes converted to numbers, keyed `redirectKey(site, from, '')`.
  A 301/302 row with an empty `to` is skipped (it would answer 404, not a blank Location). `payload-redirects.ts`
  binds it to `cms()` and is loaded by `import()` on first use, like `cron/jobs/payload-queue.ts`.
- **Cache** (`map-cache.ts`): one map per site, 5-minute TTL, single-flight; a failed load is logged once with
  `describeError`, answers 404 for that request and is not cached. Nothing at import time, no `'use cache'`.
- **Route** (`route.ts`): `legacyRoute(load = defaultLoader, now = Date.now)`, `export const GET = legacyRoute()` and
  `export const HEAD = GET`. Site from `x-site`, path from `x-public-path`, query from the request URL's search (the
  proxy appends the visitor's query to the rewrite, `proxy/decide.ts` `case 'legacy'`). 301/302 with an absolute
  `Location` (`siteOrigin(site)` + path; an absolute `to` stays), 410 plain `Gone`, 404 plain `no-store`;
  `public, max-age=3600` on 301/302/410. HEAD = same status and headers, no body. Stub doc comment rewritten.
- **Key** (`key.ts`): see Deviations.

## Endpoints

`GET|HEAD /api/x/legacy/[...path]` (already mounted; behaviour changed from a plain 404 to the row answers).

## Deviations

1. **`@engine/http` cannot import `resolveRedirect` (apps/web) or `redirectKey` (`@engine/migrate`).** `http` does not
   depend on `@engine/migrate`, `@engine/migrate` does not resolve from `packages/http`, adding it needs a
   `package.json` and `pnpm-lock.yaml` change that this ticket does not own, and `http` must not reach into
   `apps/web`. So `legacy/key.ts` restates `redirectKey()` (about 25 lines) and the route does the one-hop lookup
   itself (`map.get(redirectKey(...))`, which is all `resolveRedirect` does). `key.test.ts` pins it to the builder's
   function with a relative-path import of the migrate source (test only), so drift fails CI. `apps/web/src/server/redirects/resolve.ts`
   is untouched and now has no caller; the orchestrator may delete it, or move the normaliser into `@engine/config`
   and make both sides import it.
2. **DB test location.** The ticket's "db test" lives in `engine/packages/cms/src/collections/redirects/redirect-map.db.test.ts`
   (the `http` package cannot import `payload` or the cms test support). It imports the real `readRedirectMap` by relative
   path and binds it to the pushed database's Payload. The thin `cms()` binding in `payload-redirects.ts` is not
   exercised by a test (it is one line, and `cms()` needs the app's own database).
3. **Paging** uses pages of 1,000 with `sort: 'id'` rather than `pagination: false`, to bound each query and keep the
   page order stable.
4. **Not run against a real Next server.** The query reaching the handler rests on `proxy/decide.ts` appending `search`
   to the legacy rewrite (and its existing tests); the route reads `request.url`'s search. If Next dropped it, `?s=sold`
   rows would 404. 9.4.c (staging run) should open `/category/<id>?s=sold` once.
5. The route exports `HEAD`, but `apps/web/src/app/api/x/legacy/[...path]/route.ts` re-exports only `GET`; Next derives
   HEAD from GET there, so no change was made (not an owned path).
