## Interpretation note for the orchestrator — the ticket's named "dead groups"

The ticket named `account`, `bag-as-account`, `payment`, `order`, `offers` as dead. Those groups'
**contract keys still live in `src/messages/lexicon/*.ts`** (defaults defined in code, outside
this ticket's owned paths), and `bag` is current checkout vocabulary. What was deletable was the
**value layer** — the lexicon JSONs — and that is what 4.3.d pruned: every shop value key not
backed by a default and not named by the source, per the test's rules. A later defaults-level
cleanup (owned by the code contract) can remove the unused `defineMessages` entries; the test
will then naturally allow removing anything still referenced there.

## Deviations from the ticket, and why

- **`await connection()` added to every new page.** The `[locale]` layout's own `connection()`
  does not hold pages back (Next renders layout and page concurrently — see `shell/site.ts`),
  so pages that read cached loaders must await it themselves or the loaders run at build and the
  build fails without `DATABASE_URL`/`PAYLOAD_SECRET`. Verified by building with both unset.
- **`loadSiteSettings` lives at `src/server/site-settings.ts`** (an ESLint server-only rule forces
  server imports out of component folders; the ticket's suggested co-location was adjusted).
- **Cache tags via `@engine/cache` builders** (`workTag`, `productTag`, `settingsTag`) rather than
  literal `'works'`/`'products'`, per project convention; `@engine/cache` added to the web app's
  `package.json` dependencies (lockfile via `pnpm install`).
- **Reseller pricing spec softened** to "Wholesale tiers, agreed with our trade desk" — the
  design drawing promised account/pricing machinery that belongs to the accounts phase.
- The ticket's Verify line `pnpm vitest run engine/apps/web/src/sites …` finds no test files at
  the workspace root (vitest v5 workspace root filtering); the equivalent is
  `pnpm exec vitest run --root engine/apps/web src/sites src/shell`, used below.
