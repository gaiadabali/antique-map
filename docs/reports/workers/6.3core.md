- ✅ **6.3.b — pickStore (the nearest active store holding every line).**
  `geo.ts` (haversine km, `isInIndonesia` on the stores' own bounds box, pin validation),
  `assign.ts` (pure rule: reach → out_of_stock → no_single_store → nearest, ties by units then
  store code), `pick-store.ts` (reads active stores' pins and their sellable stock, works on a
  Payload instance or an order's transaction).
  Evidence: `pick-store.db.test.ts` — "a pin in Ubud picks the nearer of two stores",
  "ties are broken by store code" (equidistant midpoint pin → `SNR-01`, the lower code),
  "a basket no single store can fill is refused before payment and changes no stock" (refusal
  names the missing line; stock unchanged, no order rows), "a pin outside Indonesia is refused".
- ✅ **6.3.c — createOrder (one transaction).**
  `create-order.ts`: server-side details validation, bag re-parsed from the signed cookie and
  re-priced via 6.2's `quoteBag` (the request carries no price field; `expectedTotalIdr` is a
  comparison only), store picked inside the READ COMMITTED transaction with
  `lock_timeout = '5s'`, per-line `UPDATE stock_levels … AND quantity >= n RETURNING id` in
  (product_id, variant_sku) lock order as Postgres sorts it (same order as the expiry's release),
  a zero-row update rolls everything back, order inserted `pending_payment` with quoted integer
  totals, `expiresAt = now + orderExpiryMinutes` (default 60 via `DEFAULT_WINDOW_MINUTES`),
  order number from `orders_number_seq` if present else max+1 under an advisory lock, tracking
  token = 32 random bytes base64url returned once with only its SHA-256 stored, discount
  `used_count` incremented in the same transaction. One retry on a unit lost between pick and
  decrement.
  Evidence: `stock.db.test.ts` — "20 concurrent orders for the last unit: exactly one succeeds"
  (real pushed Postgres, 20 parallel `Promise.allSettled` orders on separate connections, ≥5
  queued on the row at once, 19 designed `out_of_stock` refusals, stock 0, one order) and
  "a failed line rolls back every earlier decrement"; `pick-store.db.test.ts` — "a tampered
  price in the request is ignored" (wrong `expectedTotalIdr` → `price_changed`, nothing
  created, stock unchanged; the quoted total is accepted and the order stores the server's
  figures), "the tracking token is never stored in clear" (row + lines + history hold no token;
  `tracking_token_hash` = sha256 of the returned token), "a used welcome code increments
  used_count once" (0→1 after the order, integer-rupiah discount math checked, a second order
  without a code spends no use).
