### The four constraints

1. **The default is unchanged.**
   - In a request, `invalidate.ts` still calls `revalidateTag(tag, tagExpiry(tag))` unless `now` is passed.
   - A batch with no `now` tag posts exactly `{"tags":[…]}`, the same body and the same framing bytes as before
     (test "a default-only flush posts the exact body of before this flag existed").
   - The route still calls `invalidate(tags)` with one argument for a default body. The existing test "is
     invalidate() in its in-request mode" passes unchanged.
2. **The immediate mode survives the collector and its flush.**
   - Both collectors carry `now` with each tag (`collector.ts`), and the batch keeps `now` once any caller asked
     for it (`batch.ts` `keep`).
   - `flush` posts the `now` group first, in bodies that carry `"now": true`.
   - **The receiving route ignored that flag (finding 1). It is fixed now.**
3. **It is used only on status transitions.** `isStatusTransition` (`work-invalidate.ts:63`) is true for a
   `status` change, or for a `_status` change (publish or unpublish). A title edit keeps the default. Delete keeps
   the default (finding 3).
4. **There are tests for both modes, including through a collector.**
   - `invalidate.test.ts`: `now` gives `{ expire: 0 }`; no `now`, or `now: false`, gives `31_536_000`.
   - `collector.test.ts`: there are three tests through the operation, the flush and the posted body.
   - `work-hooks.test.ts`: sold flushes with `"now": true`; a title edit flushes with no `now` key.
   - The review added route tests (`revalidate.test.ts`), including one where a batch flush runs end to end
     through the route.

**Is the Next API form right?** I checked the installed Next 16.3.6 docs,
`node_modules/next/dist/docs/01-app/03-api-reference/04-functions/revalidateTag.md`:

- `{ expire: 0 }` means "Stale content is never served, so the next request is a blocking revalidate/cache
  miss".
- That page names `revalidateTag(tag, { expire: 0 })` as the form for a route handler or webhook.
- `updateTag.md` says `updateTag` "can **only** be called from within Server Actions".

The branch uses `IMMEDIATE_EXPIRY = { expire: 0 }` (`tags.ts:45`), so the form is correct.
