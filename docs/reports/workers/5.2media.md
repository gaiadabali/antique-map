## What was built

| Piece | Where | What it does |
| --- | --- | --- |
| Publish step | `engine/packages/media/src/pipeline/{publish,sniff,store,index}.ts` (new export `@engine/media/pipeline`) | Sniffs the upload's bytes (JPEG, PNG, WebP, AVIF; anything else refused before decoding — F1), checks that sharp decodes the same type, renders the C9 ladder (AVIF + WebP) and a ≤32 px WebP blur placeholder, all re-encoded without metadata (F3). For a **work** image whose long edge is over 2,400 px, it writes a IIIF 3 level-0 pyramid capped at the gallery's `publicZoomMaxPx` (4,096): tiles first, `info.json` last, its `id` set to the public URL. | Ladder fix | `engine/packages/media/src/derivatives/index.ts` | `derivativeWidthsFor()` used to add the source's own width for **any** source, so a 6,000 px upload got a public 6,000 px derivative, beyond the 2,400 top rung and the 4,096 cap. ### Where generation runs, and why not a queued job yet

ARCHITECTURE.md §10 puts derivatives and tiles on the jobs queue, run by `/api/x/cron/jobs`. Payload creates the queue's
`payload_jobs` table only with the first registered task, and **no migration carries it** (none on main up to
`20261006_054525_indies_9_1`). Registering a task would therefore need a schema change, which this ticket may not make.

Running inside the save was ruled out. On this machine the large test image took about 40 s (about 3 min under heavy
load). Inside `afterChange` that would hold the upload's response and its database transaction open the whole time,
and a failure would fail the upload. So the pipeline runs in Next's `after()`, after the response and after the
commit, one image at a time per process. `deriveMedia()` is the whole step, so a jobs task can wrap it unchanged:
`{ slug: 'media-derivatives', handler: ({ input }) => deriveMedia(payload, input.id) }`, queued by the same hook.

### Backfill command

```bash
pnpm --filter @engine/cms media:derivatives                 # every record not ready at DERIVATIVE_VERSION
pnpm --filter @engine/cms media:derivatives --force         # rebuild all
pnpm --filter @engine/cms media:derivatives --id 98 --id 99 # just these
```

It runs against the worktree's database (like the seed: `DATABASE_URL`, else `DB_SUFFIX`) and the `S3_*` media bucket
with `MEDIA_PUBLIC_URL`. It processes one image at a time and prints a summary. It posts the expired cache tags to the
running site, or counts them as unposted when no site is reachable. It exits 1 when any record failed, so rerunning it
is the retry. Seeded and imported images always need it (their writes are outside a request), and so does staging's
catalogue.

## Found

1. **The ladder broke the public cap** (ARCHITECTURE.md §8, 4,096 px). The 5.2.a library pushed the source's full width
   as a public derivative for any source, and its test asserted 2600 → `[…, 2400, 2600]`. Fixed, and the test updated.
2. **Home and browse cards served the staff-only file URL** to every visitor. This was broken for anonymous visitors
   since 4.3/5.1, not only "until derivatives exist". Fixed.
3. **`next/image` cannot serve the media origin.** No `remotePatterns`, and one build serves every environment's media
   host, so the item lead image would have been a 400 even with derivatives. Fixed by rendering remote sources
   unoptimized; the ladder loader (archived 15.1.c) is the proper answer.
4. **OpenSeadragon needs `crossOriginPolicy` for the WebGL drawer.** Without it, tiles from the media origin taint the
   canvas and it renders black. Fixed.
5. **`db:fresh` does not drop an existing database**, despite the name. `db:drop` first gives a really fresh one.
6. **The `local.mjs start` harness does not forward `ORDER_LINK_KEY`**, which main's boot check now requires. The
   production start fails until it is exported in the shell.
7. **main's `engine/packages/cms/package.json` lists `"./admin/views"` twice** (identical values, harmless). It came in
   with the merge and was left as main has it.
8. **Payload stores an upload's pre-rotation width/height.** For an EXIF orientation 5–8 upload, `largestDerivativeWidth(media.width)`
   names a key the ladder (which uses the displayed width) did not write. This is rare for scans. Left as found.
