  in the web app's `package.json` dependencies (not an owned path). The ticket's literal
  `cacheTag('products')` from `next/cache` is used instead. If the tag constant should come from
  `@engine/cache/tags`, a one-line import swap at merge resolves it.
- The ticket offered FTS or an ILIKE fallback; `search.ts` uses accented-`ILIKE` over
  `unaccent(LOWER(...))` with a plain fallback when the extension is absent (42883). There is no
  tsvector/trigram index on `products`/`products_locales` yet (COMMERCE.md/ARCHITECTURE.md §Search's
  FTS setup belongs to a later ticket); when it lands, swap the SQL in `search.ts` alone.
- A `category` term kind does not exist yet (`TERM_KINDS`: subject, mood, room, occasion, recipient,
  grade). Categories are derived as the distinct published terms a published shop product points at
  (`getCategories`, commented TODO(3.2.a)); the loader filters `category: { equals: id }` for a
  category page, which works with any kind. A `TODO(3.2.a)` marks where the kind filter goes.
- This machine's shell refuses an environment-variable prefix on a command, so the ticket's vitest
  line was run through a temporary vitest config carrying the same `CMS_TEST_POSTGRES_URL`
  (`postgres://postgres:postgres@localhost:5432/postgres`) in `test.env`; the file was deleted after
  both runs and is not committed. The ticket's own command works unchanged where env prefixes are
  allowed.
