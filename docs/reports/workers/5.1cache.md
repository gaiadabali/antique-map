## Diagnosis — confirmed, with one correction and one addition

- **Confirmed.** `server/gallery/catalogue/catalogue.ts` tagged `listing`, `facets`, `placeTree` and `search`
  with a hand-written `'works'` tag and no `cacheLife`, so the `default` profile applied (revalidate 15 min).
  `work-invalidate.ts` cleared only `work:<uid>`; `revalidateTag` is called only in
  `packages/cache/src/invalidate.ts`; `parseCacheTag` refuses a kind-less tag, so `'works'` could never be
  posted to `/api/x/revalidate`; places, makers and terms had no invalidation hook.
- **Correction (scope).** The gallery home rail (`server/gallery/home/load-featured-works.ts`, newest three by
  `-updatedAt`) had the same bug: per-work tags only, so a newly published work could not appear on it.
- **Addition (found by the new db test).** On an update Payload's `previousDoc` is the latest *version*
  (`getLatestCollectionVersion`), not the published row. After a draft revision is saved over a published
  record, the unpublish that follows reads draft → draft, and the existing `touchesPublished` gate in
  `work-invalidate.ts` expired nothing: the unpublished work stayed listed. Fixed for works and the vocabulary
  (`hooks/published-state.ts`): on a draft → draft *update* the hook counts the record's published versions in
  the save's transaction and expires when there is one.

## cacheLife decision: `'hours'`

Every gallery catalogue scope (and the home rail, maker and place loaders) declares `cacheLife('hours')`
(stale 5 min, revalidate 1 h, expire 1 day). The tag is the freshness; the lifetime is only a backstop for a
write that announces nothing: a CLI run with no `REVALIDATE_SECRET` (the seed prints "N tag(s) not posted"), a
fix made in SQL, a media edit (see Follow-ups). Left implicit it was `default` (15 min); Next's docs ask for an
explicit `cacheLife` in every scope (and an explicit outer one wins over an inner, so the nested `placeTree`
read cannot shorten or lengthen `listing`). A shorter life would spend background recomputes on content the
tag already keeps fresh; a much longer one would let a missed invalidation linger.

## Found

- **ARCHITECTURE.md §6 vs `previousDoc`**: "Invalidation runs after the write commits" holds, but a hook that
  gates on `previousDoc._status` misses an unpublish that follows a draft revision (Payload hands the latest
  version). Fixed here; any future invalidation hook on a drafted collection should use
  `hooks/published-state.ts`.
- **`localhost` on this machine**: a WSL relay (`wslrelay.exe`) listens on `[::1]:5432` and `[::1]:9000` beside
  Docker's `0.0.0.0`. Node resolves `localhost` to `::1` first, so db tests with `localhost` in
  `CMS_TEST_POSTGRES_URL` and the server's `S3_ENDPOINT=http://localhost:9000` (from `.env.example`) time out or
  reset (`ECONNRESET`, 30 s `beforeAll` timeouts, media upload 500). Using `127.0.0.1` fixes both; the worker
  rules' example URL says `localhost`.
- The 5.4 report's "no tag kind exists" note in `server/gallery/makers/queries.ts` is updated: the maker and
  place loaders are now cached under `catalogue:gallery`.

  the shop's kinds expiring `catalogue:shop` too.
