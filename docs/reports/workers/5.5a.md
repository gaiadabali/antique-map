## Product defects found

1. **The viewer cannot open a non-tiled image (most of the gallery). Severity: high. Owner: devops/media (headers)
   or FE (`crossOrigin` on the lead image).**
   - For any image ≤ 2400 px (no IIIF pyramid), OpenSeadragon opens `viewerSrc` (the largest derivative) with
     `crossOriginPolicy: 'Anonymous'`.
   - The page's lead `<img>` has usually already loaded the same URL **without** CORS. The media origin
     (`old-east-indies.gaiada.com/_media/…`) answers a request without `Origin` with neither
     `Access-Control-Allow-Origin` nor `Vary: Origin`.
   - Chromium therefore serves the cached non-CORS response to the CORS request, and the viewer fails.
   - Reproduced outside the app on a shop derivative: plain load → loaded; the same URL with
     `crossOrigin=anonymous` → **error** (CORS blocked); a fresh URL with CORS only → loaded.
   - `curl` shows: without Origin, `200` with `cache-control: public, max-age=31536000, immutable` and no
     `vary`/`access-control-*`. With `Origin: https://indies-gallery.gaiada.com`, `access-control-allow-origin` and
     `vary: Origin`.
   - Fix: always send `Vary: Origin` (better: ACAO on every GET) on `/_media/`, or render the lead image with
     `crossOrigin="anonymous"`.
   - It is intermittent (en 390 passed once), depending on which `srcset` entry the lead picked and when.
   - 5.2.e's tiled image is not affected: tiles are never loaded as plain `<img>`.
2. **A 1×1 PNG fails the derivative pipeline** (`derivatives.status = failed`, `iiif.status = failed`), and the item
   page then has no public image. The shared `support/fixtures.ts` recto is exactly that, so `browse`/`contact`
   specs show a broken image on staging. Low severity (no real recto is 1 px). Owner: media.
3. **The "low-resolution photograph from the old site" notice** shows for any image under 1600 px, including this
   `provenance: photograph` upload that is not from the old site (`server/gallery/item/images.ts` ignores
   provenance). Low. Owner: FE/copy.
4. **No header search** (the journey's "type in the header search"): the header has no search box, so the visitor
   goes to `/search`. **No close (Esc)** on the viewer. Both are §6/§4 gaps already noted in TASKS. Owner: FE.
