## What was wrong and what I did

1. **Bilingual writes were stored as garbage.** The Local API does not take `{en, id}` pairs on one write —
   it stringifies the object into the single operation locale. New `bilingual.ts` (`isLocalePair`,
   `splitLocales`, `asEnglish`, `pairAs`) splits every row into a default-locale write plus a
   `locale: 'id'` update (the codebase idiom, `vocabulary.db.test.ts`), and `locale: 'all'` reads give the
   stored pairs back for diffing (`diff.ts` compares through `pairAs`).
2. **Payload 3.90.2 keeps locale state on the request object** (the run's key finding). A `locale: 'all'`
   read or a `locale: 'id'` write on one `PayloadRequest` poisons every later call on the same request —
   a create after an 'all' read stored only the Indonesian half; a later write after an 'id' write landed
   in `id` with unlocalized fields (`price`) lost. Found by bisecting with probe tests. Fix: `freshReq()`
   in `apply.ts` — one fresh request object per Payload call, all inside the run's transaction. Documented
   in `freshReq`'s doc comment.
3. **Products have no top-level `active` field.** Payload dropped it silently and every product row then
   reported a spurious `active: (blank) → yes` change on re-runs. Removed from `plan-shop.ts` product
   planning with a comment; `active` remains a variant's on-sale flag.
4. **cli.ts** now uses `cms()` from `../instance` instead of calling `getPayload` directly (the
   instance.test contract: "only cms's CLI and tests call getPayload").
5. **Test/lint cleanup:** removed debug `console.log(render(...))` from `import.db.test.ts`, fixed
   unnecessary regex escapes, irregular whitespace (literal BOM → `\uFEFF` escape), unused imports/vars,
   `no-control-regex` disable-comment on the control-character strip (that is exactly what it strips).
6. **`sources/index.ts` deletion** (flagged — outside my owned paths): staged by the dead run's `git rm`;
   verified dead — `git grep` finds no reference to `collections/sources` anywhere on main or the branch.
   Committed rather than resurrected; the orchestrator can restore with `git revert` if it disagrees.
