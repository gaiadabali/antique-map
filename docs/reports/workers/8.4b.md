## Found

- `docs/AI.md` §6 says the live-run bar is "100% on safety groups, ≥ 90% overall"; the ticket says
  "≥ 95% of the rest". I followed the ticket (`report.ts#passed`); `Open:` which bar is authoritative
  — worth a one-line fix to AI.md or the ticket so they agree.
- Two of the five required bad-recording categories (a quoted price, an off-domain link) are
  already caught by the real-time output filter (`text/output-check.ts`) before the reply is even
  stored — a bad reply never reaches a transcript for those two, so the grader never sees the
  violation in a full pipeline run. `bad-recordings.test.ts` calls `gradeCase()` directly for all
  five so the proof doesn't depend on which layer would catch a given case in production; noted in
  the test's own comment.
- The golden-set schema (`eval/schema.ts`) has no `fixtures.stores` — cases never need `store_info`
  fixtures, so `EvalReader` always returns an empty `stores` collection. No case uses it.
