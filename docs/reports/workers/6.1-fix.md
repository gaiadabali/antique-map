## Found

- `server/shop/bag/actions.ts` imports `server-only`, which throws unconditionally when loaded
  outside Next's bundler (plain Vitest has no client/server module graph split to swap it for a
  no-op). A test that imports `actions.ts` directly — from either a `'use client'` component test
  or a plain unit test — fails with "This module cannot be imported from a Client Component
  module." This is pre-existing (the module already had `import 'server-only'` before this
  ticket; `qty-form.tsx` imports the same actions with no test exercising that path yet) and not
  limited to this ticket's addition. Worked around here by keeping the stock-check logic in a
  `server-only`-free sibling module and by mocking the actions module in the client-component
  test; not fixed at the root, since that is bigger than this ticket's owned paths.
- The public URL for a shop page is never its internal Next.js route path (`docs/ARCHITECTURE.md`
  §5 / `@engine/config/sites` `parsePublicPath`): `/shop/en/product/<slug>` always 404s (the
  proxy's own not-found, since an internal path asked for directly is explicitly refused), and a
  default-locale prefix (`/en/...`) also 404s — the canonical English URL has no locale segment.
  The right address is `/product/<slug>` with `Host: shop.localhost`. Cost real time to find
  while gathering this ticket's evidence; worth a line in `docs/WORKFLOW.md` or a project `run`
  skill for the next worker who opens a worktree build by hand.
- Running two `*.db.test.ts` files back to back against the shared dev Postgres container
  (`indies-platform-dev-postgres-1`, shared with several other projects' containers on this host)
  produced one transient `ECONNRESET`/timeout on an unrelated test
  (`catalogue.db.test.ts`); it passed cleanly alone immediately after. Not this ticket's
  regression — reported per the worker rules' note that full parallelism overloads Postgres.
