## Found — the blocking defect (not this ticket's to fix)

**`order` is not a registered public surface.** `engine/packages/config/src/sites/routes/
surfaces.ts` (`SURFACE_ROUTES`) and `table.ts` (the shop's `routes.en`/`routes.id` maps) list
`cart`, `checkout`, `tracking`, `product`, … — no `order`. The proxy's own doc (`engine/packages/
http/src/proxy/decide.ts`'s header, point 6) is explicit: *"anything else — an internal path asked
for directly included — [goes] to the site's not-found route … nothing under `/gallery/` or `/shop/`
is ever served at its internal address."* Since `order` matches no surface, every request for
`/order/{number}` (and `/order/{number}/simulate`) is rewritten to the shop's own not-found page —
**even a real order and its correct tracking token**. Reproduced directly, bypassing Playwright and
the app's own `notFound()` entirely:

```
$ curl -s -o /dev/null -w "%{http_code} %{time_total}\n" -H "Host: shop.localhost" \
    "http://127.0.0.1:4290/en/order/100005?t=uh3lJpaNBF_Xs5BV32NkBmnMcOoiJifaKcJ_qwE-I8Y"
404 0.047328
```

The response's own RSC flight data confirms the proxy rewrote the request to `shop/en/not-found`
*before* the order page's loader ever ran (the order page's own route segment never appears in the
matched tree). This is not the app's `notFound()` (a wrong token or number) — the order existed and
the token was its real one.

**Blast radius**, everything that builds a `/order/…` URL hits the same wall:
- the order page itself (`app/(shop)/shop/[locale]/order/[number]/page.tsx`)
- the simulate page (`.../order/[number]/simulate/page.tsx`)
- 6.3a's checkout action (`server/shop/checkout/actions.ts:153`, outside this ticket's owned
  paths, **not edited**): `redirect(`/${locale}/order/${created.number}?t=${created.trackingToken}`)`
  — the buyer is redirected here straight off checkout
- this ticket's own `actions.ts` (`payAction`'s `redirectUrlFallback`, `simulateAction`'s
  `orderPath`) and `order-view.tsx`'s Pay form fallback

**Recommended fix** (outside this ticket's owned paths — `engine/packages/config/src/sites/**` is
shared routing config, not `sites/shop/payment/**` or the order app route): add an `order` entry to
`SURFACE_ROUTES` (`internal: 'order/[number]'`, `sensitive: true` — it carries a tracking token in
the URL, same as `tracking`) and to both locale route maps in `table.ts`. Once registered,
`siteHref('shop')('order', { number }, locale)` replaces every hand-built `/${locale}/order/…`
string above (`order-view.tsx`'s `trackingHref` already shows the right pattern).

## Two more bugs found and fixed in this run (in scope, fixed)

1. **`putBackInBagAction`** (`server/shop/payment/actions.ts`) redirected to `/${locale}/cart` —
   the *internal* route segment, not the public alias the proxy's surface map expects (`/bag`,
   `/id/keranjang`). Same class of bug as the `order` one above, but `cart` *is* a registered
   surface, so this one is fixable in-owned-path: now built through `siteHref('shop')('cart', {},
   locale)`, matching `order-view.tsx`'s own `trackingHref`.
2. **`sendOrderCreatedEmail`**'s tracking link (`server/shop/payment/email/order-created.ts`)
   hardcoded `/${locale}/track/${token}` — wrong for `en` (the default locale is unprefixed:
   `/track/…`, not `/en/track/…`) and wrong for `id` (the public alias is `/lacak/…`, not
   `/track/…`). Now built through `siteHref('shop')('tracking', { token }, locale)`.
   `order-created.test.ts`'s link assertions updated to the corrected (and now actually valid)
   shape; still 6/6 passing.
