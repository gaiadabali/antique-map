## Found

- **The nav link needed a line in `payload.config.ts`, which this ticket does not own.** Payload
  3.90's `AdminViewConfig` (`node_modules/payload/dist/admin/views/index.d.ts`) has no `nav`
  property — the only way to add a sidebar link for a custom view is the top-level
  `admin.components.afterNavLinks`, which lives in `payload.config.ts`'s `admin.components`
  object (beside the existing `views: adminViews()` line this ticket does own). I added one
  line, `afterNavLinks: ['@engine/cms/admin/views#LeadsNavLink']`, additive and owner-gated
  (`admin/leads/nav-link.jsx`). Flagging it explicitly since it is outside the ticket's listed
  owned paths — please re-review that one line, or move the wiring if there is a preferred owned
  seam for it.
- **The products picker shows only the product's name, not its SKU**, in Payload's own
  relationship UI (`useAsTitle: 'name'` on `products`, which this ticket does not own). Showing
  both would need either a virtual/combined title field on `products` or a custom relationship
  `Field` component — both bigger than this ticket's scope. Searching the picker by SKU already
  works (`products`' own `listSearchableFields`). Named test "the products picker offers only
  published products" is met via `filterOptions`; the SKU-in-row request is a follow-up.
- **"Open the source" links to admin pages only, not each item's public page.** `works` has no
  stored `slug` field — the public URL's slug is derived at render time by the site loaders, which
  this ticket does not own, and guessing the algorithm risked a broken link. The admin edit page
  link (stock number + title) is there; the public link is a follow-up once a shared "build this
  item's public href" helper exists to call from here.
