## Reading it

- **Passes the 5.5.d bar** (≥ 90 performance, 100 accessibility) on every run. TBT, CLS and script size are well
  inside budget.
- **Misses the LCP budget**, where the shop gate also sat at 2.0–2.7 s (`docs/gates/shop.md`):
  - On **/browse**, the first card image waits about 1.1 s before it starts (load delay) and takes about 1.1 s to
    load. Lighthouse's own checks pass: the request is in the initial document, `fetchpriority=high` is applied and
    the image is not lazy. The likely costs are the **cross-origin media host** (`old-east-indies.gaiada.com/_media/`
    needs its own connection: the image has a high-priority `<link rel="preload">`, but there is no `preconnect` to
    that origin) and three render-blocking CSS
    chunks. This is unverified. Owner: FE/perf. A `preconnect` to the media origin is the cheap first try.
  - On **home**, the LCP is a **text** paragraph with about 2 s of render delay. `font-display` passes, so it is
    not a font-swap issue. The render-blocking-insight audit names three CSS chunks. Cause not proven. Owner: FE.
  - **TTFB about 650–740 ms** in every simulated run is the throttled RTT plus this workstation's route to staging.
    The shop gate measured from a container on the staging host because the workstation was unsteady. A run there
    would likely cut the gap, but not the browse load delay or the home render delay.
- JSON evidence: one run per page, the one at the median score, in `docs/reports/workers/5.5c/`
  (`browse.json` = run 3, `product-200.json` = run 3, `home.json` = run 1). All 9 JSONs were read for the tables above.
