## The route contract (for 8.2)

The session cookie is `chat_sid`: HttpOnly, SameSite=Lax, Secure on https, session-scoped, `Path=/api/x/chat`. Every write needs a same-origin `Origin` (or `Sec-Fetch-Site: same-origin`), otherwise it gets 403. The site comes from `Host`. Bodies are JSON, at most 8 KB.

**`POST /api/x/chat/session`**
- Body: `{ turnstileToken: string, locale: 'en'|'id' }`.
- Success: `200 { ok: true, resumed: false, limits: { maxMessageChars: 1000, messagesPerSession: 30 } }` plus `Set-Cookie`.
- With a valid cookie, the same call is the re-challenge: `200 { ok: true, resumed: true }`.
- Errors are `{ error: { code, message } }`:
  - 400 `bad_request` or `challenge_required`
  - 403 `challenge_required` (Turnstile failed) or `bad_request` (origin)
  - 429 `rate_limited` with `Retry-After`
  - 503 `disabled` or `unavailable`

**`DELETE /api/x/chat/session`** → `204`. It deletes the conversation and clears the cookie.

**`POST /api/x/chat/message`**
- Body: `{ text: string, locale: 'en'|'id', pagePath?: string }`. The public path of the page the chat was opened on gives the model the item.
- The answer is always `text/event-stream`, one `data: <JSON>\n\n` per event. The last event is exactly one `done` or one `error`.
- Events:
  - `{type:'delta', text}`: plain text that has passed the checks (a small Markdown subset: paragraphs, lists, bold, links to our origins / wa.me / mailto).
  - `{type:'status', label}`: a progress line. It never names a tool.
  - `{type:'card', kind:'work'|'product'|'store', id, title, url, image: string|null, statusLabel?, priceLabel?}`. `priceLabel` appears only on the shop. `id` is the public id (a work's `publicId`, a product's slug).
  - `{type:'handoff', channel:'whatsapp'|'email', href, label}`. `href` is `https://wa.me/…?text=…` or `mailto:…?subject=…&body=…`.
  - `{type:'lead_form', kind:'ask'|'sell'|'partnership'|'contact'|'chat', itemIds: string[], consentText, consentVersion, consentToken}`.
  - `{type:'done', outcome:'answered'|'handoff'|'refused'|'blocked'}`.
  - `{type:'error', code, message}`. `code` is one of `rate_limited`, `budget_exhausted`, `disabled`, `unavailable`, `too_long`, `session_limit`, `session_required`, `challenge_required`, `bad_request`.
- A refusal before the turn starts is the same stream (handoff events where settings allow, then `error`) under its status:
  - 400 `bad_request`
  - 401 `session_required`
  - 403 `session_limit`, `challenge_required` or `bad_request`
  - 413 `too_long`
  - 429 `rate_limited` with `Retry-After`
  - 503 `disabled`, or `budget_exhausted` with `Retry-After`, or `unavailable`
- A turn that started answers 200, even when it ends `refused` or `blocked`.
- Aborting the request (Stop) aborts the upstream call.

**`POST /api/x/chat/consent`**
- Body: `{ consentToken, consent: true, name, whatsapp?, email?, preferredChannel:'whatsapp'|'email', message?, idempotencyKey }`.
  - `whatsapp` must be E.164; spaces and dashes are allowed.
  - At least one contact is required, and the preferred channel must have one.
  - `idempotencyKey` is 8–100 characters of `[A-Za-z0-9_-]`, generated on the client.
- Success: `200 { ok: true, reference: 'L-<id>' }`. Repeating the same token and key returns the same reference.
- Errors: 400 `bad_request` (invalid, or no consent tick), 401 `session_required`, 410 (token unknown, expired after 30 min, already used, or another session's), 429 `rate_limited` (5 per hour per address).
