## Deviations
1. **Driver images reuse the existing purge.** `shop/fulfilment` already has `purgeDriverImages` (7.1.b: 30 days after the last move into delivered/cancelled, objects removed, group cleared, order stays, history note). `runRetention` calls it in pages instead of a second implementation. Consequence: the driver-image period is not part of `RetentionPolicy` (it is `DRIVER_IMAGE_RETENTION_DAYS`).
2. **`createLead(deps, request)`** takes a request envelope `{ input: unknown, turnstileToken, ip }`, because the ticket's order (Turnstile, then rate, then validate) needs the token and address beside the fields.
3. **The rate limit is 10 posts a minute per address (ticket), SECURITY.md §2.10 says lead forms 5 an hour.** I followed the ticket; the doc needs a decision.
4. **The email carries no name, items or message excerpt** (ticket), where AI.md §4 says kind, name, items and the first 300 characters. The ticket is the stricter rule; AI.md should be edited to match.
5. **Recipients:** `site-settings.<site>.leadNotifyEmails`, else `<site>.contact.email`; if neither, one `PLACEHOLDER` warning is logged and nothing is sent (the lead is kept).
6. **Spam leads are deleted 30 days after `createdAt`** (there is no reliable "marked spam at" except the history array). A closed lead with no `closedAt` is never deleted (no clock).
7. **Chat sessions linked to a lead are deleted too** (ticket). AI.md §3.4 says such a session "keeps only the lead's summary"; the lead already carries its own message, and `leads.chatSession` falls to null on delete.
8. **Two edits outside the listed paths**, both one line: `engine/packages/cms/package.json` gained the export `"./jobs/retention"` (the http route cannot reach the sweep otherwise). I did **not** add the route to `ENGINE_ROUTES` in `packages/http/src/manifest.ts` (not mine, and the chat routes are absent from it too); parity tests still pass.
9. **Lexicon:** keys added in the middle of the existing alphabetical-ish blocks (`lead.error.*` before `partnership.apply`, `partnership.form*` in place) to avoid end-of-file conflicts with the other branches.
10. **Turnstile in the browser:** loaded with an explicit-render script by the island only on this page; there is no CSP yet (SECURITY B2), so `challenges.cloudflare.com` must be added to `script-src`/`frame-src`/`connect-src` when it lands. The site key is `TURNSTILE_SITE_KEY`, read in `page.tsx` at request time and passed as a prop (no `NEXT_PUBLIC_*`); unset, the form is switched off with a message and the button disabled; the secret unset, every check fails (closed).

## Review round (Opus + phase-5 reviewer)

Applied review fixes from code-review round 1.

**Changes:**

1. **Split caller context from visitor input.** `createLead(deps, request)` now takes `request: { input: unknown; context: LeadContext; turnstileToken: string | null; ip: string | null }`. Defined and exported `LeadContext = { readonly kind: LeadKind; readonly site: LeadSite; readonly source: LeadSource; readonly consentVersion: string }` (in `input.ts`). `parseLeadInput(input: unknown, context: LeadContext)` validates only the visitor's fields: name, whatsapp, email, preferredChannel, message, locale, items, and `consent`. It merges `context` into the returned `LeadInput`. It validates the context values against the KINDS/SITES/SOURCES lists and the consentVersion length, and throws an Error if a context value is invalid (programming error).

2. **Refuse unknown or reserved keys.** If `input` is not a plain object, or carries any key outside {name, whatsapp, email, preferredChannel, message, locale, items, consent}, the result is `{ ok: false, errors: { form: LEAD_ERROR_KEYS.invalid } }`. That set excludes kind, site, source, consentVersion and consentAt. Replaced the existing "drops stray keys" test with "refuses a stray or reserved key (kind, site)".

3. **Consent in the service.** `input.consent` must be exactly `true`, or the string `'on'`/`'true'` from a form. Otherwise add the error `consent: LEAD_ERROR_KEYS.consent`. Removed the separate consent check from submit.ts, which now passes `consent: form.get('consent')` inside input. Kept submit.ts's early `parseLeadInput` call before Turnstile so a form with mistakes doesn't spend the token.

4. **Normalise contacts with checkout's rules.** Local `0812…` WhatsApp number becomes `+62812…` via E.164 normalization. Email is trimmed and lower-cased. An invalid value keeps its current per-field error key. Added the tests "a local 0812 number is normalised to +62" and "an email is lower-cased".

5. **Rate limit before Turnstile.** In `createLead` the order is now: the token-shape check (no token, or longer than 2048 → 'challenge'), then `deps.allow(ip)` (→ 'rate'), then Turnstile verify (→ 'challenge'), then parse, then store, then notify. Updated the module comment. Added the test "a failed challenge still counts against the limit, so the eleventh post is refused before siteverify": the eleventh call must not invoke verifyTurnstile.

6. **Route manifest.** In `engine/packages/http/src/manifest.ts`, added `route('/api/x/cron/retention', 'WEB', 'cron', POST),` next to the other cron lines, with a short comment (daily retention sweep, TASKS.md 9.1.d). Tests pass with the new route: route-parity and proxy-matcher tests updated via existing test infrastructure.

7. **Updated every caller and test** to the new shapes, including partnership-lead.db.test.ts. The partnership caller's context is `{ kind: 'partnership', site: 'shop', source: 'form', consentVersion: CONSENT_VERSION }`.
