## What was built

- `engine/packages/migrate/src/redirects/load.ts` — `loadRedirects(payload, options)`: `dedupeLegacyUrls` +
  `buildRedirects` (the builder still throws on a duplicate `from`, a self-loop or a chain, before anything is read or
  written), then an upsert keyed on `from` within the site. The pure parts are exported and unit tested: `planLoad`
  (the diff: create / update / unchanged / prune list), `isUnchanged` (`to`, `code`, `source`), `chunk` (batches).
  Writes go in batches of 500 (`batchSize` overridable), **one transaction per batch**: create, then update, then (only
  with `prune`) delete; a refused row rolls its batch back and the error propagates, earlier batches stay whole.
  `dryRun` reads and plans but never calls `beginTransaction` or a write. Counts: rows, gone, unresolved, created,
  updated, unchanged, pruned.
- `engine/packages/migrate/src/redirects/works-from-db.ts` — every work with a `legacy.productId` and a `publicId`,
  read through the Local API with `select` of only `legacy.productId`, `publicId`, `title`, `_status`; published and
  unpublished both (the builder's rule turns an unpublished one into "unresolved", never a row). Slug derived from the
  title exactly as the item page does (`slugOf`, restated from `apps/web`'s `view-model.ts`).
- `engine/packages/migrate/src/redirects/load-cli.ts` + `load-args.ts` — boots Payload through `@engine/cms/instance`
  from `DATABASE_URL` and `PAYLOAD_SECRET` (both must be in the environment; refused by name when missing, never
  printed; an error's text is scrubbed of anything URL-shaped). Prints one counts line per site. `unresolved-out=<dir>`
  writes `unresolved.<site>.json` (array of `{ from, reason }`, what 9.4.c's `--unresolved` reads), also on a dry run.
- `engine/packages/migrate/package.json` — script `redirects:load` (`payload run src/redirects/load-cli.ts --`), plus
  `@engine/cms` and `payload` (3.90.2, same as cms) as dependencies; `pnpm-lock.yaml` updated by `pnpm install` for
  them (not hand-edited).
- `engine/packages/migrate/tsconfig.json` — type-check excludes `*.db.test.ts` (see Found).

## Arguments are bare words (deviation from the ticket's `--flags`)

`payload run` rebuilds `process.argv` from positional arguments and **drops every `--flag`** (`@engine/cms`
`db/cli.ts` `argument()`). `--dry-run` would vanish and the run would write. So the CLI takes words, and the mode is
**mandatory**: `dry-run` or `apply`. Nothing defaults to a write; a `--flag` that does arrive is refused by name.
Checked by hand through `pnpm`: `gallery` -> "name the mode"; `gallery --dry-run` -> refused by name; `gallery dry-run`
without env -> "DATABASE_URL is not set".

| Ticket                 | Word                       |
| ---------------------- | -------------------------- |
| `--site gallery`       | `gallery` (or `site=gallery`), `shop`, `all` |
| `--dry-run`            | `dry-run` (the other mode is `apply`) |
| `--prune`              | `prune` |
| `--unresolved-out DIR` | `unresolved-out=DIR` (use an absolute path; the CLI runs in the package folder) |

## Staging command (orchestrator)

From the checkout on the staging host, with `DATABASE_URL` and `PAYLOAD_SECRET` in the environment (the app's own):

```bash
OUT=/tmp/redirects-9.4load && mkdir -p $OUT
# 1. counts only, nothing written
pnpm --filter @engine/migrate redirects:load all dry-run unresolved-out=$OUT
# 2. load (creates the rows)
pnpm --filter @engine/migrate redirects:load all apply unresolved-out=$OUT
# 3. idempotence: must print created=0 updated=0 pruned=0 for both sites
pnpm --filter @engine/migrate redirects:load all apply
```

Then 9.4.c's tool with `--unresolved $OUT/unresolved.gallery.json` (and `.shop.json`). Add `prune` only to delete a
site's rows the current inventory no longer produces. The legacy route caches each site's map for 5 minutes
(9.4.b `map-cache.ts`), so a changed row can take that long to answer.

Output per run: `works read: N (M published)`, then `<site>: rows=… gone=… unresolved=… | created=… updated=…
unchanged=… pruned=…`.

## Found

- **Staging works need `legacy.productId`.** A work without it is not in the lookup, so its old URL is "no work for
  legacy id N" (unresolved). If the 44 staged works came from the sample seed rather than an import that carries the
  old ids, step 1 will show `rows` small and `unresolved` large: that is the data, not the loader.
- **Shop site.** The shop rules look products up in the same `works` list by slug and map category paths from
  `categories`, which is `{}` here (as in 9.4a's CLI). Expect the shop to load mostly gone (`/account`) rows and list the rest
  unresolved until the shop's products and a reviewed category map feed the lookup.
- `prune` deletes every row of that site not produced, including `source: editor` rows (the ticket's literal wording).
  An upsert likewise overwrites an editor row whose `from` is produced. Say if prune should spare editor rows.
- `packages/migrate` now depends on `@engine/cms` and `payload`; `payload`'s own comment in `cms/src/instance.ts` says
  cms alone declares it. Same pinned version, one store copy, but it is a second declaration.
- `check:filesize` fails on `site-shell.tsx` on this base (above).
