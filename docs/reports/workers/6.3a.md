## What the GLM run got right (kept as-is)

Read every uncommitted file against `tickets/6.3a.md` and the merged core
(`@engine/cms/shop/orders`, `@engine/cms/shop/pricing`) before keeping anything:

- `checkout/page.tsx` redirects an empty/missing bag to `/bag` before rendering; never caches.
- `read-checkout.ts` prices the review from the database (`quoteBag`) — no client-supplied price or
  quantity is ever read.
- `actions.ts`'s `submitOrderAction` calls `createOrder` with the raw bag cookie, the form details,
  the bag's welcome code and `expectedTotalIdr` exactly as the merged core's own header comment
  specifies; `quoteFeeAction` calls `quoteCheckout` the same way, taking no stock.
- Every `OrderRefusal`/`PickRefusal`/`DiscountRefusal` kind maps to a lexicon key in
  `refusal-text.ts`, each proven to render non-empty text in **both** locales
  (`refusal-text.test.ts`), with `out_of_stock`/`no_single_store` naming only buyer-facing product
  names (never an id) via `itemNames`/`nameOf`.
- `pin-picker.tsx` is a real Google-Maps-or-fallback picker: with `GOOGLE_MAPS_BROWSER_KEY` it loads
  the Maps JS API by script tag with Places autocomplete and a draggable pin; without one (the local/
  CI case) the fallback — paste a Maps link or type lat/lng — fully works, re-validated server-side.
- `/api/x/geocode` parses all three Google Maps link shapes, checks `isValidPin` + Indonesia bounds,
  calls out only when `GOOGLE_MAPS_SERVER_KEY` is set, and is rate-limited the way `/api/x/collect`
  is — all proven by the committed `geocode.test.ts`.
- The bag's checkout button already pointed at the `checkout` route (`bag-view.tsx`), and the
  `checkout` surface was already registered in `@engine/config/sites` — no change needed there.
- No new npm dependency; all new files under 300 lines.

## What was wrong, and what I changed

1. **Typecheck failure** — `sites/shop/checkout/copy.ts` annotated `checkoutText`'s internal
   `Messages` as `Messages<string>`, which `tsc` rejects (`createMessages` infers a narrower key
   union; a function that only accepts that union isn't assignable to one that must accept any
   `string`). Let it infer instead (`copy.ts`).
2. **A wrong test assertion** — `copy.test.ts`'s `SHARED_KEYS` list asserted a `cart.quantity`
   lexicon key that the checkout page never actually borrows (confirmed by grepping every `text(…)`
   call in the checkout's own files). Removed it from the list.
3. **A locale-fragile test** — `refusal-text.test.ts` compared `formatRupiah(50000)`'s real output
   (Indonesian `Intl.NumberFormat` inserts U+00A0 between "Rp" and the figure) against a literal
   with a plain space (U+0020), so it failed by one invisible character. Changed it to assert
   against `formatRupiah(50000)` itself.
4. **Formatting drift** — `pnpm run format:check` flagged 9 of the new files; ran `prettier --write`
   on exactly those.
5. **A broken eslint-disable** — `pin-picker.tsx` carried
   `// eslint-disable-next-line react-hooks/exhaustive-deps`, but this project's eslint config does
   not define that rule at all, so the disable comment itself was a lint error
   (`--max-warnings=0`). Removed the comment; the effect (map built once per key, not re-run on
   every pin change) is already documented by the line above it.

Committed in three steps (explicit paths, no `git add -A`): the kept GLM work, the typecheck/test
fixes, and the formatting/lint fixes.
