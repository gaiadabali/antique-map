## Interface (stable for 7.2 / 7.3) — `@engine/cms/shop/fulfilment`

- `moveOrder(payload, { orderId, to, actor, reason?, now? }) → MoveResult`
- `attachDriverImage(payload, { orderId, file: { buffer, mimetype?, size? }, actor, now? }, deps?) → AttachResult`
- `driverImageUrl(payload, orderId, ttlSeconds, deps?) → string | null`. **Deviation from the ticket:** the ticket
  wrote `driverImageUrl(orderId, ttlSeconds)`. Payload is added as the first argument because the key must be read
  from the order. TTL is 1 s–15 min (`DRIVER_IMAGE_URL_MAX_TTL`); anything else throws `RangeError`.
- `purgeDriverImages(payload, now, deps?) → { purged, failed }`
- `reassignOrder(payload, { orderId, toStoreId, actor, now? }) → ReassignResult`
- `handBackOrder(payload, { orderId, actor, reason, now? }) → HandBackResult`
- `actor` is `req.user` as Payload gives it (`collection: 'users'`, `role`, `store`). Every result is a
  discriminated union on `ok`, with a `refusal` code for the lexicon and a plain English `message`.
  - Move refusals: `not_staff`, `not_found`, `not_your_store`, `no_change`, `move_not_allowed`,
    `driver_image_required`.
  - Attach refusals: `not_staff`, `not_found`, `not_your_store`, `order_closed`, `empty_file`, `too_large`,
    `not_an_image`, `unreadable_image`, `storage_unavailable`.
  - Reassign refusals: `not_allowed`, `not_found`, `wrong_status`, `same_store`, `store_unavailable`, and
    `not_enough_stock` (which also carries `lines`).
  - Hand-back refusals: `not_allowed`, `not_found`, `not_your_store`, `wrong_status`, `reason_required`.
- Also exported: `judgeMove` (pure), `sniffImageType`, `driverImageStoreFromEnv`, the constants, and the types.
- The purge route factory `driverImagePurgeRoute({ refuse })` is in `src/shop/fulfilment/http.ts`. It is not
  exported from the index on purpose (see Follow-ups).

## Subtasks

- ✅ **7.1.a — transitions, history, who moves what.**
  - Every move runs in one READ COMMITTED transaction (the payments seam): the order row is locked `FOR UPDATE`,
    the move is judged, then the status is set by compare-and-set.
  - The judgement is the collection's own `statusMoveRefusal` (3.5.c, unchanged), plus two checks only the core
    can make: whose store the order belongs to, and the driver image.
  - Each change writes one `orders_history` row with `actor='user'`, `by_id`, from, to and the reason.
  - A cancel from a holding status puts the units back on the order's store's shelf, in lock order. A cancel from
    `pending_payment` also gives back the discount code's use, as expiry does. A cancel from `on_the_way` returns
    nothing.
  - Evidence: `transitions.test.ts` covers the full status × status table for each role. In
    `fulfilment.db.test.ts`: "a store user cannot move a status backward", "… skip a status", "… another store's
    order", "every transition writes a history row", "cancelling a held order returns its stock once" (3
    concurrent cancels).
- ✅ **7.1.b — the driver image.**
  - The type is sniffed from magic bytes (JPEG, PNG, WebP). The name and mimetype are ignored, and SVG is refused.
  - The size limit is 10 MB, measured on the bytes received rather than the declared `size`.
  - The image is re-encoded with sharp through `@engine/media/derivatives` `makeDerivatives`: turned upright,
    metadata stripped, at most 1600 px on the long edge, written as WebP.
  - It is stored at `orders/{id}/{ms}-{hex}.webp` in the media bucket. That is a private prefix: the public
    policy covers only `derivatives/` and `iiif/`. The record is updated in one transaction with a history row.
    A replaced image is deleted.
  - `driverImageUrl` signs a SigV4 presigned GET. The purge deletes every object under the order's prefix 30
    days after the last history row into `delivered` or `cancelled`, then clears `driverImage` by
    compare-and-set and writes a `system` history note.
  - Evidence:
    - `image.test.ts`: Exif with camera and GPS is gone after re-encoding; portrait and landscape are capped at
      1600; undecodable bytes throw.
    - `presign.test.ts`: matches **AWS's published worked example** signature exactly.
    - `fulfilment.db.test.ts`: "an image that is not an image is refused" (renamed .exe and a text file, both sent
      as `image/jpeg`) and "an oversize image is refused".
    - `hand-back-and-images.db.test.ts`: replacing an image deletes the old one, the URL signs only the current
      one, `unreadable_image`, `order_closed`, and the purge at 31 days but not 29, with a second run purging 0.
    - `http.test.ts`: the purge route.
- ✅ **7.1.c — reassign and hand-back.**
  - Reassign is for the owner or an editor, on a `paid` or `processing` order (COMMERCE §4). The target store must
    be active and have a pin.
  - For each product and variant in lock order, the lower store id is touched first. The new store is debited
    with the order code's own atomic `takeStock`, and the old store gets the units back. If any line is short,
    every short line is collected and the transaction is rolled back, so neither store's stock changes.
  - On success the order's store, snapshot and `distance_km` are updated (the fee is unchanged), and a history row
    names both stores.
  - Hand-back is for store staff only, on their own store's order, in `paid`, `processing` or `waiting_driver`,
    and needs a reason. It raises `needsAttention` (the payments core's `flagOrder`) and writes a history row.
  - Evidence: `fulfilment.db.test.ts` "a reassign to a store without stock leaves both stocks unchanged" (two
    lines, one fillable, so the rollback of a partial move is proven) and "a reassign moves the stock exactly
    once" (two concurrent reassigns: one is `ok`, one gets `same_store`). Plus `hand-back-and-images.db.test.ts`.

## Found

- **The private bucket.** The masters bucket cannot hold driver images: `masters-writer.json` allows writes only
  under `masters/` and no deletes, and the 30-day purge must delete. Images therefore go to the media bucket under
  `orders/`, which `PUBLIC_MEDIA_PREFIXES` / `media-public-read.json` leave private. This should be recorded in
  COMMERCE §9 / SECURITY F4.
- **No presigned GET in `@engine/media/storage`** (only a PUT), and `@engine/cms` has neither the AWS SDK nor
  sharp as dependencies (adding them would change `pnpm-lock.yaml`, which this ticket does not own).
  - Presign: `presign.ts` is a small hand-written SigV4 query presign, held to AWS's worked example.
  - Re-encode: goes through `makeDerivatives`, which always renders AVIF as well as WebP and includes the source
    width. That costs extra encodes, and a tall portrait takes two passes.
  - Proposed swap, owned by media: export `presignGet(target, key, ttl)` (SDK `getSignedUrl`) and
    `reencodeImage(bytes, { maxEdge, format })` from `@engine/media`. The core already takes them through ports
    (`DriverImageStore`, `Reencoder`), so the change is one line each.
- **COMMERCE §4 vs hand-back.** A store may hand back in `waiting_driver`, but reassign is only for `paid` or
  `processing` (§4). An owner first steps the order back one status (an allowed move), then reassigns. I followed
  the doc rather than widen reassign.
- **Reassign does not clear `needsAttention`.** The payments core raises the same flag for late or doubled
  payments, so clearing it on reassign could hide a payment alert. The owner clears it in the admin. 7.2's owner
  view should offer that.
- **An owner cancel from `pending_payment` while a Midtrans attempt is open.** A later settlement then meets a
  `cancelled` order. The payments `decide` handles a non-pending order by flagging, not applying, but the
  refund/void path is §12's (phase 7.x).
