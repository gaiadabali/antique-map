## Found

1. **The mock products CSV cannot publish without real images** — every row in `seed/shop/data/products.csv`
   carries an empty `image_files` (no real photography yet, AGENTS.md D19), and a product needs at least one
   image to publish; `pnpm --filter @engine/cms seed --layer shop --publish` rejects all of them. The ticket's
   own Verify block anticipated this ("if the seed needs images, use the fixture route instead and say so") —
   `ops.ts`'s `setup` now makes its own fixture products with a generated placeholder image when fewer than two
   sellable published ones are found. Not a product defect; `docs/gates/shop.md` carries the detail.
2. **`tests/e2e/admin/local.mjs`'s `fixtures()` cannot run outside a Next request any more.** Since `291f012`
   added `vocabulary-invalidate.ts` (a cache-invalidation hook on `terms`/`makers`/`places`/`works` writes using
   Next's `after()`), and `after()` throws outside a request scope — which every plain `payload run` script is —
   `fixtures()`'s own `terms`/`makers` creation now fails every time. This affects every local `GATE_DB=local`
   gate that calls it, not just this one. Reported, not fixed in `fixtures.ts` (outside this ticket's owned
   paths): worked around by giving this gate its own `accounts` op in `ops.ts` (owned), touching only `stores`
   and `users` — collections the hook never watches.
3. **`tests/e2e/admin/local.mjs`'s `start()` does not forward `ORDER_LINK_KEY`** to the server it spawns, a boot
   check requirement since 6.6 (`.github/scripts/start-server.sh` was fixed for CI in `3b62e2d`, this script
   was not). Reported, not fixed in `local.mjs` (outside owned paths) — worked around locally with
   `node --env-file=.env.local tests/e2e/admin/local.mjs start`.
4. **`.env.example` still does not supply `BAG_COOKIE_KEY`, `GALLERY_HOSTS`, `SHOP_HOSTS`, `MIDTRANS_MODE`,
   `CRON_SECRET`, or SMTP settings** a from-scratch worktree needs to boot the shop at all — already
   `docs/gates/phase-6-checks.md` Finding 3 and `docs/gates/shop-payment.md` Finding 3; still not fixed
   (outside this ticket's owned paths either). Worked around in this worktree's own `.env.local` and
   `engine/apps/web/.env.local` (gitignored, not committed).
5. **A Postgres connection pool opened before `db:drop`/`db:fresh` serves wrong (non-erroring) reads
   afterwards** — hit mid-ticket when the running server kept answering "out of stock" for a freshly stocked
   product after the database under it was dropped and recreated. Restarting the Next server (not just the
   database) cleared it. Noted for anyone resetting a worktree's database while its server is already running.
