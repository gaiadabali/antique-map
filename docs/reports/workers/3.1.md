## Found (contradictions)

1. **One key vs two key pairs.** DEPLOYMENT.md §6 and §8 say the app has one key for both buckets. The engine
   reads `MASTERS_ACCESS_KEY_ID`/`MASTERS_SECRET_ACCESS_KEY` separately (`@engine/media` `storage/env.ts`), and
   the boot check requires both (`config/boot-check/platform.ts`). `storage/policies/plan.mjs` models two users
   and refuses one user twice. The script fills both pairs with the one key `uindies` and fails when the secrets
   differ.
2. **Retention purge.** DEPLOYMENT.md §6 says the key "may delete under `orders/` and `imports/`", but
   `masters-writer.json` grants no delete and no write outside `masters/`. The purge will get `AccessDenied`.
3. **Media bucket CORS.** DEPLOYMENT.md §6 says its CORS admits both origins (the viewer fetches `info.json`).
   No document in `@engine/media` covers it, so neither `storage:policies` nor the script applies one. The
   gallery's viewer fetching `/_media/` on the shop host is cross-origin.
4. **Mail sender variables.** DEPLOYMENT.md §8 names `MAIL_FROM_GALLERY`/`MAIL_FROM_SHOP`; the boot check
   requires `SMTP_FROM_ADDRESS`. The skeleton writes `SMTP_FROM_ADDRESS`.
5. **First owner.** DEPLOYMENT.md §2 says the first owner is made at provisioning, with credentials in
   `/etc/indies/staging-admin/`. No script makes it (5.1 did it by hand), and the old credentials name the
   dropped databases. It needs a step after the first migration on `indies_db`.
6. **Ticket order.** The ticket says "dry-run, apply, then retire", which cannot work. Port 4030 is `uig`'s, and
   both hostnames are `uig`'s and `uoei`'s CloudPanel sites, so the apply refuses until they are retired (by
   design: it checks the port, the vhost's upstream and any other vhost serving our hosts). The runbook order is:
   dry run → secrets check → retire → `--create-sites` apply → vhost editor → TLS.
7. **TLS.** `clpctl site:delete old-east-indies.gaiada.com` removes its certificate. The new site needs one
   covering both names (CloudPanel's Let's Encrypt, the gallery host as an extra domain). DNS does not change.
8. **Building the release.** A hand release built on this Windows workstation packs win32 sharp binaries, which
   cannot load on Helios. It must be built on Linux (WSL or a container).
9. **CORS origins.** 8.5's `archive-masters` CORS admitted both origins. The admin is on the shop host only (Q1),
   so the script narrows it to `https://old-east-indies.gaiada.com` (first apply: one CORS change).
10. **Stale comment.** `.env.example` (not owned) still says the masters key "OEI's key writes only under
    print-files/".
