## What to build

1. **`pnpm data:seed --layer <layer>`** — a CLI in `engine/packages/cms/src/seed/` that runs the 3.7.a importer
   (`runImportPath` / `runImportFile`) over the layer's files. Layers: `vocabulary`, `gallery-sample`,
   `gallery-full`, `shop`. Flags `--dry-run` and `--publish` pass straight through to the importer's `RunOptions`.
   Idempotent: the same command twice changes nothing (the importer already proves this — do not break it). Also
   wire the missing root script `pnpm data:import --kind <kind> --file <path> [--apply]` (DATA.md §3; the import
   CLI already exists).
2. **Vocabulary layer** — places with their historical names and parents, the grade/technique/subject/category
   terms, and the two sites' `site-settings` defaults (DATA.md §2's Vocabulary row), from files committed under
   `seed/` (the gazetteer is already committed there). Runs on every environment, staging and production included.
3. **Gallery sample layer** — a deterministic pick of **50** normalised records; copies of their legacy photographs
   at 640 px (about 3 MB the set) committed under `seed/gallery/data/images/` with alt text from the record;
   antiques import files written in CONTENT-MODEL §9's columns. Every seeded antique arrives as a **draft**.
4. **Gallery full layer** — reads the normalised output in `LEGACY_DATA_DIR` (default `../indies-legacy-data`; the
   1,823 records sit at `indies-gallery/normalised/<label>/records.jsonl` — regenerate with the migrate normalise
   CLI if the label is missing). Never committed. From each record: stock number, `publicId` = the old product id
   (so old gallery addresses work, DATA.md §6), title and text as normalised, status `available` or `sold` as the
   old page showed, `location` `singapore`. **The old USD prices are not loaded at all** — no `asking_price`
   anywhere, not even blank: the column is absent from the generated files, and the asking price stays the owner's
   to type (DR-3; Q14). Rows the normaliser marked `review` are **flagged, never silently cleaned** (DATA.md §4) —
   carry the mark into the record so the admin shows them in the review queue.
5. **`pnpm data:purge-seed`** — deletes every `SEED-` product, store and stock row; refused when `NODE_ENV` is
   production (the codebase's env-check idiom). **`pnpm db:fresh`** loads the vocabulary, gallery sample and shop
   mock layers (it builds the schema today; add the seed step after the migration).
6. **Tests** (`*.test.ts` beside the code, plain unit where no database is needed; `*.db.test.ts` where it is):
   the sample pick is deterministic (two runs → identical files); seeding is idempotent; a seeded work carries no
   `askingPrice` and no price in any public projection; `publicId` equals the old product id; a `review` row lands
   flagged; the shop mock layers load; `purge-seed` refuses production (with the env overridden).
