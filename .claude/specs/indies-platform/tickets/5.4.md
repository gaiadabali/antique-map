## Build, in this order (commit after each)
1. **Loaders** (`server/gallery/{makers,places,pages}/`): Payload Local API, `overrideAccess: false`, `_status: 'published'` wherever the collection has drafts, `site: 'gallery'` for pages, an explicit `select` of only shown fields (never `askingPrice`, notes or staff fields). `loadMaker(slug, locale)`, `loadMakerIndex(locale)`, `loadPlace(path: string[], locale)` (walk the place tree by slugs, `/places/java/batavia`), `loadPlaceIndex(locale)`, `loadPage(slug, locale)`. Each returns a plain serialisable view model or `null`. Works on a maker or place: **available first, then sold** (status), published only, through the work-card projection. Db tests (`*.db.test.ts`): a draft page is null; another site's page is null; a draft work is not in a maker's list; `JSON.stringify` of every result has no `askingPrice`.
2. **Maker pages** (5.4.a): `/makers` index (name, life dates, count) and `/makers/{slug}`: name with life dates and roles, biography, available works then sold ones (EXPERIENCE §7). Unknown → `notFound()`.
3. **Place pages** (5.4.a): `/places` index (a drill-down by region, never a 100-link list) and `/places/{...path}`: modern name as H1, **historical names under it** ("Batavia · Djakarta"), the note when the CMS has one, child places, available works, sold works.
4. **Pages from `pages`** (5.4.b): render the page's blocks with one small renderer per block type the collection defines (prose, figure, work rail, FAQ, call to action; a "zoom figure" may render as a plain figure with a link to the item — say so in the report). 5. **Board:** `pnpm tasks:report 5.4.a` once steps 2–3 render, `5.4.b` after step 4. Never tick 5.4.c.
