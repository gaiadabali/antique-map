## What to build (exact)
Every label and admin description bilingual `{ en, id }` like `stores`. Field names exactly as CONTENT-MODEL §6.
`site` everywhere is a `select` of `gallery` | `shop`, required.

1. `leads` — fields of CONTENT-MODEL §6: `kind` (required select ask|sell|partnership|contact|chat), `site`,
   `source` (chat|form|page), `payload` group (name, whatsapp text validated E.164 `^\+[1-9]\d{6,14}$` when set,
   email, preferredChannel whatsapp|email, message textarea max 2000, locale en|id, consentVersion, consentAt
   date), `items` (relationship hasMany to `works` and `products` — `products` does not exist yet: relate to
   `works` only and leave a `// 3.3 adds products` comment), `chatSession` (relationship to `chat-sessions`),
   `status` (select new|contacted|in_progress|closed|spam, default new), `statusHistory` array (status, by →
   users, at date) appended by a `beforeChange` hook when status changes, `firstReplyAt` date, `notes` textarea.
   Access: read/create/update/delete **owner only** (`isOwner`). No public create (the server's lead service
   writes with the Local API).
2. `partners` — name (required), contact group (person, whatsapp, email, phone), terms textarea,
   `productsCarried` (text array for now; `// 3.3 relates to products`), notes. Owner only.
3. `chat-sessions` — fields of CONTENT-MODEL §6 (`site`, `locale`, `startedAt`, `lastMessageAt`, `items`,
   `transcript` array of { role user|assistant, text, at }, `ipHash`, `labels` text array, `usage` group {inputTokens,
   outputTokens, costUsd number}, `outcome` select refused|blocked|handoff|lead, `lead` → leads) plus
   `expiresAt` date (= lastMessageAt + 30 days, set by a `beforeChange` hook; export the pure function
   `chatExpiry(lastMessageAt: Date): Date` and unit-test it). Owner only.
4. `events` — the fields of ANALYTICS.md §4 (read it; at least `site`, `name` select of the §4 catalogue names,
   `at` date indexed, `path`, `ref` text, `props` json, `day` text indexed `YYYY-MM-DD`). Owner reads; nobody updates
   or deletes through the API (`update: () => false`, `delete: () => false`); create owner only.
5. `pages` — `site`, `kind` (page|story|collection), `title` (localized), `slug` (required), `intro`
   (localized textarea), `hero` → media, `body` (localized richText), `works` → works hasMany, `seo` group
   (title, description localized). Drafts on (`versions: { drafts: true }`) with `read` and `readVersions`
   both set: owner/editor read all, public read published only (use `access/published.ts`). Create/update/delete
   owner and editor. Compound unique index on (`site`, `slug`).
6. `redirects` — a plain collection (no plugin): `site`, `from` (path starting with `/`), `to`, `code` (301|302,
   default 301), `source` (legacy|editor|slug-change), `hits` number default 0. Compound unique index
   `indexes: [{ fields: ['site', 'from'], unique: true }]`. Owner and editor manage; public read none.
7. Global `site-settings` in `globals/site-settings/index.ts` exactly as the paragraph under CONTENT-MODEL §6
   (groups `gallery` and `shop`; the shop adds `checkoutEnabled`, `delivery { bands[] { upToKm, feeIdr (integer) },
   freeOverIdr (integer, default 500000) }`, `welcomeDiscount` as a text code for now (`// 3.3 relates to
   discounts`), `orderExpiryMinutes` default 60, `storeAlerts`). Read and update owner only.
   Add it to `GLOBALS` in the registry.
