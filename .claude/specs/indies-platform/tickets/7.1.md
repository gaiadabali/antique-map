## Build (commit after each)
1. **Interface first** — `shop/fulfilment/index.ts` exporting, with JSDoc:
   - `moveOrder(payload, { orderId, to, actor, reason? }): Promise<MoveResult>` — transitions `paid → processing → waiting_driver → on_the_way → delivered`, plus `cancelled`; a store user only forward by one step and only on their store's order; owner/editor any legal move; one transaction, order row locked; a `history` row (who, when, from, to, reason) for **every** change; cancel/expiry from a holding status returns stock once.
   - `attachDriverImage(payload, { orderId, file: { buffer, mimetype, size }, actor }): Promise<AttachResult>` — type-sniffed from bytes (not the name), size-limited, re-encoded with `sharp` (EXIF stripped), stored in the private bucket under `orders/{id}/…`; `driverImageUrl(orderId, ttlSeconds)` returns a short-lived presigned GET; a sweep `purgeDriverImages(payload, now)` deletes images 30 days after delivery.
   - `reassignOrder(payload, { orderId, toStoreId, actor })` — owner/editor only: returns stock to the first store and decrements at the second **in one transaction** with the atomic decrement; refused (both stocks unchanged) if the second store cannot fill every line. `handBackOrder(payload, { orderId, actor, reason })` — a store user hands back with a reason; flags it for the owner.
   - Result types are discriminated unions with plain refusal reasons (the lexicon in 7.2 maps them).
2. **The implementations** with unit tests for the pure parts (the transition table).
3. **Db tests** `fulfilment.db.test.ts`, by name: "a store user cannot move a status backward"; "a store user cannot skip a status"; "a store user cannot move another store's order"; "every transition writes a history row"; "an image that is not an image is refused" (a renamed `.exe`, a text file); "an oversize image is refused"; "a reassign to a store without stock leaves both stocks unchanged"; "a reassign moves the stock exactly once" (two concurrent reassigns → one wins); "cancelling a held order returns its stock once". Run with `CMS_TEST_POSTGRES_URL=postgres://postgres:postgres@localhost:5432/postgres pnpm vitest run --maxWorkers=2 <path>`.

## Rules that hold
Stock moves are single atomic SQL statements inside one transaction; no read-then-write. Access is enforced in the core, not the UI. Never trust a mimetype or a filename. Plain `ValidationError` messages. No file over 300 lines.
