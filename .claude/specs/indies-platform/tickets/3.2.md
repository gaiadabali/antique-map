## What to build
Exactly subtasks 3.2.a–3.2.e of TASKS.md, with these decisions already made:
- `sources` become a plain-text `references` array on `works` (each: `citation` text, `note` textarea); delete the
  `sources` collection folder and its registry line.
- `works.publicId`: integer, unique, indexed; a `beforeChange` hook on create assigns `max(publicId)+1` with a
  floor of 100000 when empty (a migrated work keeps the old site's id). Test the pure function
  `nextPublicId(currentMax: number | null): number`.
- `works.askingPrice`: whole US dollars as an integer, field-level access read/update `owner` only (Q14). It must be absent for editors, store users and the public.
- `works.status`: `available | on-hold | sold`, default `available`; `location`: `singapore | jakarta`.
- `aiDraft` group on works: for each draftable field (title, description, objectType, date, places, subjects,
  dimensions) a `{ drafted: checkbox, verifiedBy → users, verifiedAt }` entry; the publish guard refuses while any
  `drafted` is true and `verifiedAt` empty, naming the fields.
- Publish guard (3.2.c): on `_status: 'published'` refuse with a Payload `ValidationError` whose message names each
  missing field in plain words, English and Indonesian (title, objectType, date, a primary image with alt text,
  grade).
- 3.2.e: if `engine/packages/config` on your branch exports `SITES` with `SITES.gallery.works` (task 2.2 adds it),
  read the uid prefix and stock-number pattern from there; if it does not exist on your branch yet, leave the
  constants with a `// TODO(2.2-merge): read SITES.gallery.works` comment and say so in the report — the
  orchestrator finishes it at merge. Media read for `store` users: only media whose `subject` is not a work; the
  full-resolution file field to owner and editor only.
