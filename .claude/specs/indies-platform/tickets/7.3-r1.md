## Correction to 7.3.md (orchestrator, 2026-10-05)
The tracking page is the **`tracking` surface** already in `engine/packages/config/src/sites/routes/surfaces.ts`: `internal: 'track/[token]'`, `index: true`, `sensitive: true`. The URL is **`/track/{token}`** (and its Indonesian path from the route table) — the token in the path is the credential. **Not** `/track/{number}?t=`: the proxy drops a query string on a surface rewrite. Build links with `siteHref('tracking', { token })`; never hand-write the path. `/track` with no token is the index ("find my order": an order number + the buyer's email or WhatsApp → the tracking link sent again by email; rate-limited; it never reveals whether an order exists). Read how the proxy treats a `sensitive` surface (no-store, noindex) in `@engine/http` and rely on it.

So the page is `app/(shop)/shop/[locale]/track/[token]/page.tsx` (+ the index `track/page.tsx`), and the loader is `loadTracking(token)`: SHA-256 of the presented token, compared in constant time against the order's stored hash (the hash column is unique — look it up by hash), `null` otherwise. The 404 for an unknown token must be identical to any other 404.

The **order-created email** (pending payment) is the helper session's 6.5 (`sites/shop/payment/email/`). Yours (7.3.b, committed in `8d5136a`) sends on `paid` and every later status — make sure its links use `siteHref('tracking', { token })` too. Note the notifier never holds the token in clear after checkout: if it cannot build the link, link to the `/track` index instead and say so in the report.
