## Build (commit after each step, explicit paths)
1. **Loader** `sites/shop/payment/load-order.ts`: `loadOrderForBuyer(payload, number, token)` → a projected view or `null`. The view has number, status, `expiresAt`, lines (name, variant label, qty, line total), totals, the store's area, the buyer's locale, and the latest attempt's state. It also has a `needsAttention` reason when the order is expired but a payment arrived. Compare `sha256(token)` to the stored hash with `timingSafeEqual`. A wrong number and a wrong token are the same `null`. Use `overrideAccess: false` where Payload is used, or a narrow SQL `SELECT` of only those columns. Uncached (`await connection()`).
2. **Order page** `order/[number]/page.tsx` (`?t=`): `null` → `notFound()`. `noindex`, `Referrer-Policy: no-referrer`, no prefetch. It renders by status:
   - `pending_payment` with time left shows the order summary, the deadline, and a **Pay** button. That button is a server action that calls `openPaymentAttempt`, with `finishUrl` = this page. Snap mode loads Snap's pop-up with the client key, server-rendered as a prop and never `NEXT_PUBLIC_*`, falling back to `redirectUrl`. Simulate mode goes to step 3's page.
   - Pending or confirming shows the §7/§8 texts. Poll while the page is visible (≈5 s, stopping when hidden or on a final status) and keep a "Check again" link that works without JavaScript. "I have paid" only refreshes.
   - `paid` and later statuses show the confirmation: the order number, the store area, and the tracking link to `/track/{number}?t=`.
   - Failed shows "Try again" (same order, inside the window).
   - `expired` shows the §8 text with "Put these back in my bag". That is a server action that rebuilds the bag cookie from the order's lines through the existing bag write in `@engine/cms/shop/pricing` (product, variant, qty only), then redirects to the bag, which re-prices.
   - A late payment on an expired order shows the "we'll contact you on WhatsApp today" text.
   - A server error shows "Something went wrong on our side" with a reference id (not a stack).
   - `openPaymentAttempt` refusals (`not-payable`, `window-closed`) map to these states, never to a crash.
3. **Simulator page** `order/[number]/simulate/page.tsx`: built **only** when `paymentsConfigFromEnv()` says simulate. Otherwise `notFound()`, and production refuses it through `assertSimulatorAllowed`. Pass `simulatorProvider(config, id => `/${locale}/order/${number}/simulate?attempt=${id}&t=…`)` so the attempt's redirect lands here. Four buttons (Settle, Pending, Deny, Expire) are server actions that `emit(attempt, action)` and POST `.body` to the app's own `/api/x/webhooks/midtrans`, then redirect back to the order page. The page carries a plain "Test payment — no money moves" banner.
4. **Order-created email** `sites/shop/payment/email/`: `sendOrderCreatedEmail(payload, { orderId, trackingToken, locale, origin })` builds the text and simple HTML from the lexicon in the buyer's language. It holds what was ordered, the amounts **as stored on the order** (never re-priced), the pay-by time, and the tracking link `/track/{number}?t=`. It sends through `payload.sendEmail`. It logs no token. It never throws to its caller: it returns `{ ok }` and logs a failure without the token. **Do not wire the call into the checkout.** The orchestrator adds one call in 6.3a's action at merge. Put the exact line it should add in the report.
5. **Tests**
   - `load-order.db.test.ts` (pushed database; helpers in `engine/packages/cms/src/shop/orders/orders-db.test-support.ts`), all named: "a wrong token is null", "a wrong number is null", "the view carries no email, phone or address", "an expired order with a late payment shows the staff text".
   - `email.test.ts`, with a fake `sendEmail`: "the email states the stored totals, not a re-price", "the email carries the tracking link and the token appears nowhere else in logs", "both languages render every key".
   - `tests/e2e/shop/payment.spec.ts`, at 390 px with simulate mode: from a seeded pending order (create it through `createOrder` in a setup step) → order page → Pay → simulator Settle → the page shows paid with the tracking link. Pending → the confirming text. Expire → "Put these back in my bag" refills the bag. Plus a wrong token gives a 404, and axe is clean at 390 and 1280 px.
