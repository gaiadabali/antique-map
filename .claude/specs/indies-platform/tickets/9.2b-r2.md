## Rules that fail this ticket (beyond run 1's)
- Money is **integer rupiah** from the order's own totals. Never re-price, never round twice, never sum
  `props.total` from events.
- A store user or an editor gets the panel-less state. All record reads go through the Local API with
  `overrideAccess: false` and the owner's user (run 1's `findAll`). SQL only through `sql.ts`, with bound
  parameters, behind `DashboardContext`.
- **Load the shop panels one at a time**, as run 1 now does in `loaders/index.ts`, so a page never fans out past a
  panel's own few queries.
- Fulfilment times come from the order's recorded status moves (paid → processing → on the way → delivered),
  per store. Orders waiting now count by current status. The expired and cancelled share is over orders created
  in the period.
- Payments: method mix and the expired-unpaid rate come from `orders`/`payment-events`. "Flagged" means
  `payment-events.outcome` values that are not a clean settle (read `shop/payments/decide.ts` for the outcome
  names). Show counts only, with no order ids or customer data.
