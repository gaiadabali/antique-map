## What to build
1. **Import (3.7.a)** `import/` — parse CSV (and XLSX if `xlsx`/`exceljs` is already a dependency; otherwise CSV
   only and say so — do not add a dependency for XLSX without listing it as a follow-up): antiques by stock number,
   products by SKU (variants by `parent_sku`), stores by `store_code`, stock by store + SKU + variant SKU, discounts
   by code. Idempotent upserts through the Local API (`overrideAccess: true` is correct here — a staff-run import —
   but log who ran it); a **dry run** that validates everything and writes nothing; a **report** listing every
   rejected row with file, line number and a plain reason, and counts of created / updated / unchanged. One
   transaction per file so a crash leaves nothing half-imported. Exposed as `pnpm --filter @engine/cms import --file
   <path> --kind <antiques|products|stores|stock|discounts> [--dry-run]` and as an owner-only admin action (an
   upload form posting to a server action or endpoint under `/api/x/import`, **owner only**, size-limited).
2. **Gallery seed (3.7.b)** `seed/gallery/` — load the 1,823 normalised legacy records (the migrate package's
   output; read its README for where the normalised JSON lives or how to produce it) into `works` (drafts for rows
   marked `review`, published otherwise only if the publish guard passes; makers, places and terms linked or
   created; **legacy prices never loaded into any public field** — a legacy price goes to `askingPrice` only if
   DATA.md says so, else nowhere), with the pilot set's images as `media` (alt text from the record). The seed is
   idempotent (by stock number).
3. **Seed CLI** `seed/cli.ts` — `seed --gallery`, `seed --shop` (imports 3.7c's CSVs through the importer), `seed
   --all`.
