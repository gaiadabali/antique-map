## The spec — `tests/e2e/shop/gate.spec.ts`, 390 px, one buyer journey, real UI only
1. A guest adds **two different in-stock products** from their product pages. Discover them from the data, don't hard-code; both must be held in full by one store (`pickStore`, no split orders).
2. The bag shows both. Go to checkout and fill contact and address. Set the pin through the picker's **fallback** (type lat/lng; it works without a Maps key): a point near the store that holds both (Denpasar default centre `-8.6705, 115.2126` if that store is there).
3. The review shows a **delivery fee and a total**. Assert total = items − discount + fee, read from the page as integers. Pay.
4. On the order page (`/order/{token}`): Pay → simulator **Settle** → the page shows paid, the order number and the tracking link. Capture the order number and token from the URL.
5. Read back on the server (a `payload run` child process, as `payment.spec.ts` does; never in Playwright's own process): the order is `paid`, its store is the store that holds every line, and that store's `stock_levels` fell by exactly each line's qty (read before and after).
6. **Email:** via the Mailpit API (`MAILPIT_URL` env, default `http://localhost:8025`), the order-created email to the buyer's address exists. It holds the order number and the totals, and its tracking link starts with the site's own origin (`SITE_ORIGIN` env: the local shop origin, or the staging origin later). Skip **only** this step when `MAILPIT_URL=none` (staging's Mailpit is loopback-only; the orchestrator reads it on the host), and print "SKIPPED: email (MAILPIT_URL=none)".
7. **Abandoned order:** a second guest buys one unit and does **not** pay. Note that store's stock. Move the order's `expires_at` to 10 minutes ago (server child process, **your database only**). Call the sweep: `POST /api/x/cron/sweeps` with the cron secret header the route expects (read `engine/packages/cms/src/shop/payments/http/cron.ts`). Then: the order is `expired`, the stock is back by exactly that qty, a **second** sweep changes nothing, and the order page shows the expired text with "Put these back in my bag".
8. axe is clean on bag, checkout, order (pending and paid) at 390 and 1280 px.
`BASE_URL` comes from `E2E_PORT` locally. Also support `E2E_BASE_URL` (a full origin), so the same spec can run against staging later. Steps 5 and 7 need DB access: gate them behind `GATE_DB=local`, and print "SKIPPED (no db access): …" otherwise. **Nothing else may skip.**
