## What to build
1. **Loaders (6.1.a)** in `server/shop/catalogue/`: categories, a listing (category filter, sort newest/price
   asc/desc, pagination), search (Postgres full text on name/description in the locale, with `unaccent`; a plain
   `ILIKE` fallback is acceptable if the trigram/FTS setup is not on the products table — say so), and the product
   page (variants, images, `relatedWork` → the gallery item's public id and title only). Every Payload call:
   `overrideAccess: false`, `_status: 'published'`, explicit `select`. Availability: one aggregate read of
   stock-levels joined to active stores, computed server-side into `available: boolean` per product and per variant
   — never expose store ids, codes or quantities. `'use cache'` + `cacheTag('products')` on the catalogue reads;
   availability is **not** cached (it decides a purchase — AGENTS.md).
2. **Pages (6.1.b)**: category pages, search page (query from `searchParams`, inside `<Suspense>`), product page
   with a variant picker (client component for the selection only; the add-to-bag button posts to a placeholder
   server action that 6.2's shell replaces — leave a clearly named stub), price via `formatRupiah` (integer rupiah),
   "From the archive" link to the related gallery item on the gallery host (absolute URL from `SITES`), "Out of
   stock" state that disables adding. All copy from the lexicon (en + id), all styles tokens, 390 px first.
3. `generateMetadata` uses `@/server/seo` (`pageMetadata`, `productJsonLd` with the integer price and availability)
   — the SEO library is on `main`; if it is not on your branch, leave a `// TODO(9.3)` and say so.
