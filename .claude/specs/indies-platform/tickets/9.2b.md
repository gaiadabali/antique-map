## Rules that fail this ticket
- **Owner-only** (DR-10, ANALYTICS §8): the view and its loaders answer only `owner`; an editor or store
  user gets the panel-less state, never an error page with data hints. All Local API reads with the acting
  user, never `overrideAccess: true`.
- **No personal data, ever**: nothing stored holds an address, user agent, full referrer or query beyond the
  redacted `props`/`ref` the table already has; the dashboard renders no raw `path` with a `q=` query that
  collect did not already redact (it did — trust the table, add nothing).
- Business numbers come from business records — revenue and orders from `orders`, leads and reply times from
  `leads`, chats from `chat-sessions` — never from beacon events (ANALYTICS §1); a WhatsApp/email tap is a
  tap, never a lead.
- **Days are the `day` field** (UTC+8, stamped at collect) — never re-derive buckets from `at` in JS; a
  timezone off-by-one is a wrong dashboard, not a cosmetic bug.
- Bilingual copy (`en` + `id`) for every label, the 3.6 pattern. No raw styles; the admin's own look, no new
  tokens.

## What to build
1. **The loaders** in `server/analytics/dashboard/` — pure functions of (site, period) over the Local API
   and SQL where Payload has no grouping: visitors (sessions and page views a day from `events`, top paths,
   referrer hosts, `utm` sources, device classes, locales), search (top `search.submitted` queries;
   **zero-result queries** — the buying list), antiques (most viewed and most zoomed items, views → ask rate,
   by object type, maker, place from `item.viewed`/`item.zoomed`/`ask.clicked` props), asks and sells (taps
   by channel and context; lead counts by kind from `leads`, excluding leads flagged spam; time to first
   reply against the same-working-day promise), chat (sessions, hand-offs by channel, hand-off rate, leads
   captured, refusals and blocks, from `chat-sessions`). Periods: 7 · 30 · 90 days or a range, **compared
   with the period before** (the delta on every number). One `loadDashboard(site, period)` the view calls;
   keep each panel's query its own file.
2. **The view** at `/admin/dashboard` — the registry line, the barrel export, one tab per site labelled with
   its site, the period picker, the gallery panels of ANALYTICS §8 above (Visitors, Search, Antiques, Asks
   and sells, Chat), and empty states that say "no events yet" rather than zeros-with-deltas. The shop tab
   renders its placeholder panels as "run 2" stubs, not broken grids.
3. **Mounting**: follow the registry's contract exactly — a package specifier
   (`@engine/cms/admin/…#Name`), never an app-relative path — so both apps' generated `importMap.js` stay
   identical; regenerate them on your branch. If the import map refuses the path, stop and report rather
   than improvising a relative import.
