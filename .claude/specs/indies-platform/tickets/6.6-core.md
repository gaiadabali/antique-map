# Ticket 6.6-core — Staff-quoted delivery fee: statuses, order creation, the quote move, expiry, notifications

**Lane:** sonnet (Opus reviews before merge — money, stock and the webhook) · **Task:** TASKS.md 6.6 (the orchestrator adds it) · **Branch:** `w/6.6core` (cut from `main`, checked out) · **Report:** `docs/reports/workers/6.6-core.md`

## The decision (user, 2026-10-06 — read `TASKS.md` Log)
Staff enter each order's courier fee **before** the buyer pays; the buyer always pays the final price. Checkout takes no fee and shows no estimate (the distance fee table is retired). Stock is **held** from order placement. Staff have **2 h** (`site-settings.quoteWindowMinutes`, default 120) to quote; the buyer then has **60 min** (`orderExpiryMinutes`) to pay. Plus two orchestrator decisions: **(A)** the order link is stored encrypted (AES-256-GCM) so emails reuse the buyer's one link — no more rotation; **(B)** emails are sent by the core **after each moving transaction commits**, once per (order, status).

## Build (commit after each step; every step has its tests)
1. **Statuses.** `awaiting_quote` first in `ORDER_STATUSES`, in `HOLDING_STATUSES`, labels en "Awaiting delivery price" / id "Menunggu ongkos kirim". Status moves: `awaiting_quote → pending_payment` (the quote move only), `awaiting_quote → cancelled` (staff: owner, editor, the order's store users), `awaiting_quote → expired` (the sweep only). Nothing else enters or leaves it.
2. **Fields** (Payload definitions only): `site-settings` shop `quoteWindowMinutes` (integer 15–1440, default 120); `orders.trackingTokenEnc` (text, `NEVER_EXPOSED` like `snapToken`); `orders.notifiedStatuses` (the once-per-(order, status) record — a `select hasMany` of statuses or json; `NEVER_EXPOSED`). Regenerate types; `pnpm check:generated` clean. Tell the report exactly what the migration must add (the enum value, the three columns).
3. **Order link at rest.** `shop/orders/link-key.ts`: `ORDER_LINK_KEY` (32 bytes, base64; refused at boot when missing outside tests — add it to the boot check's host secrets), `sealToken(token) → string` / `openToken(sealed) → token|null` with AES-256-GCM, random 12-byte IV, auth tag, versioned prefix. `createOrder` stores `trackingTokenEnc = sealToken(token)` beside the hash (the hash stays the lookup). Never log either.
4. **createOrder without a fee.** No delivery quote, no distance bands: `pickStore` = the nearest **active** store holding every line, anywhere in Indonesia (drop `outside_reach`/band checks; keep `outside_indonesia`, `no_single_store`). Totals: `deliveryFee = null`, `total = subtotal − discount` until quoted. `expectedTotalIdr` compares against items − discount. Status `awaiting_quote`, `expiresAt = now + quoteWindowMinutes`. Stock decrement exactly as now.
5. **The quote move.** `shop/orders/quote.ts` `quoteDeliveryFee(payload, { orderId, feeIdr, actor })` — one transaction, order `FOR UPDATE`: refuse unless `awaiting_quote` and `expiresAt > now` (`not_awaiting_quote`, `expired`); `feeIdr` a safe integer 0–10 000 000 (`invalid_fee`); actor must be owner, editor, or a store user of the order's store (`forbidden` — reuse 7.1's actor rules in `fulfilment/actor.ts`). Set `totals.deliveryFee = feeIdr`, `totals.total = subtotal − discount + feeIdr` (from the stored row, never from the request), status `pending_payment`, `expiresAt = now + orderExpiryMinutes`, a history row (actor, fee). Plus an HTTP handler the admin can call (copy `fulfilment/http.ts`'s shape and auth; mount path `/api/x/orders/quote` is the shell's to add — export the handler and say so).
6. **Expiry.** The sweep (`payments/jobs.ts`) also expires `awaiting_quote` orders past `expiresAt` (no Midtrans status check needed — there is no attempt) through the same once-only `expireAndRelease`. Staff cancel from `awaiting_quote` releases the same way.
7. **Notify from the core, after commit (B).** `notifyOrderEvent` claims `(orderId, to)` atomically in `notifiedStatuses` (`UPDATE … WHERE NOT (to = ANY(…)) RETURNING` — a lost claim sends nothing) and builds the link from `openToken(trackingTokenEnc)` — **delete the rotation** (`newTrackingToken` here). Call it after the transaction returns in: `createOrder` (`awaiting_quote` — "we're confirming your delivery price"), `quoteDeliveryFee` (`pending_payment` — "your price is ready: {total}, pay by {time}", the link to `/order/{token}`), `applyPaymentStatus`/`markPaid` (`paid`), `moveOrder`, `reassignOrder` (store alert), the sweep (`expired`), staff cancel. The `afterChange` hook stays for admin-UI writes and goes through the same claim, so nothing double-sends. Mail failure never throws. Templates in `notify/templates.ts`, both languages, amounts as stored. The **web app's** `sendOrderCreatedEmail` becomes redundant — say so in the report (the shell removes it).
