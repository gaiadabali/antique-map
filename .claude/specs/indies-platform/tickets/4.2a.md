## What to build
One folder per component in `shared/ui/<name>/` with `<Name>.tsx`, `<Name>.module.css`, `index.ts`, and a
`<Name>.test.tsx` (vitest + @testing-library/react if present in the repo; otherwise `react-dom/server`
`renderToStaticMarkup` assertions). Components: Button (variants primary | secondary | quiet, sizes, `asChild`-free
— render `<a>` when `href` is given), TextLink (wraps `next/link` with **`prefetch={false}` always**), Input,
Select, Checkbox, Textarea (each with label, hint and error slots wired by `id`/`aria-describedby`), Card,
Badge, Eyebrow, Hairline, Header shell (slots: logo, nav, actions; a mobile menu button with `aria-expanded`),
Footer shell, FormMessage (info | success | error, `role="status"`/`"alert"`), Dialog (native `<dialog>`,
focus returns to the opener, Esc closes), Toast (a `role="status"` live region), Skeleton.
Rules: CSS Modules reading **only** semantic tokens (`var(--color-…)`, `var(--space-…)` etc.) — `pnpm check:tokens`
must stay green; no copy strings inside components (labels come in as props); every interactive element has a
visible `:focus-visible` ring from `--color-focus`; hit targets ≥ 44 px; server components unless state is needed
(`'use client'` only on Dialog, Toast, Header's menu button). Export everything from `shared/ui/index.ts`.
Files under 300 lines.

## Tests
Per component: renders its label/children; error state sets `aria-invalid` and links the message; TextLink renders
without prefetch (assert the prop reaches `next/link`, or mock it); Dialog closes on Esc in a jsdom test if jsdom is
configured, else skip with a comment.
