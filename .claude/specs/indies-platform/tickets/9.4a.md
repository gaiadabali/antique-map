## What to build
1. `migrate/src/redirects/rules.ts` — one pure function per legacy URL shape of DATA.md (gallery: product pages by
   old id/slug → the new item URL built from the work's `publicId` and slug; `/category/{id}-{slug}` with its query
   handling (`?s=sold`, `?o=newest` kept as browse filters; `?p=`, `?page=` dropped); `/storage/products/…` images;
   `/account/…` → gone; shop: the 673 archived paths → product or nearest category or unresolved). Each returns
   `{ kind: 'redirect', to, code: 301 } | { kind: 'gone' } | { kind: 'unresolved', reason }`.
2. `migrate/src/redirects/build.ts` — `buildRedirects(input: { site; urls: string[]; works: { legacyId: number;
   publicId: number; slug: string; published: boolean }[]; categories: Record<string, string> }) → { rows:
   RedirectRow[]; unresolved: { from: string; reason: string }[] }`. A destination that is not published is
   unresolved (never redirect to a draft). Normalise `from` (path + only the meaningful query keys, lower-case
   host stripped). No two rows share a `from` per site; no row's `to` is another row's `from` (no chains) — the
   builder fails loudly if either happens.
3. `migrate/src/redirects/cli.ts` — reads the two inventories and a works JSON (path argument; a small fixture is
   enough until 3.7 seeds the real works), writes `redirects.<site>.json` and `unresolved.<site>.json` to an output
   directory argument, prints counts. Nothing is written into the repo by tests.
4. `apps/web/src/server/redirects/resolve.ts` — `resolveRedirect(map: ReadonlyMap<string, { to: string; code:
   301 | 302 | 410 }>, path: string, search: string): { status: 301 | 302; location: string } | { status: 410 } |
   null` using the same normalisation as the builder (export it from one shared module in `migrate` and import it),
   one hop only.

## Tests (by name)

"an unpublished destination is unresolved, never redirected"; "fails on a chain or a duplicate from"; "an account

inventory with a generated fixture of works that asserts every one of the 7,665 URLs gets exactly one outcome
(`rows + gone + unresolved === 7665`), and the same for the 673 shop paths.
