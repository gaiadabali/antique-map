## Build (commit after each)
1. **Checkout without a fee.** Remove the delivery-fee quote from the checkout (`quoteFeeAction`, the fee box, the bag's free-delivery hint). The review shows items, discount and "Items total"; under it, the line (lexicon) "Delivery price confirmed by our team — usually within 2 hours. You pay nothing until you've seen the final total." The pin stays (it picks the store). Refusals: keep `outside_indonesia`, `no_single_store`, `out_of_stock`, `price_changed`; drop the fee-table ones. The bag page drops its fee/threshold lines.
2. **Hydration-safe inputs** (found on staging by 7.4): inputs typed before hydration are reset. Make the checkout form's fields uncontrolled (`defaultValue`, `name`) and read them with `FormData` on submit — never reset them on hydration. A test: type into the server-rendered form before hydration, then hydrate — the values stay.
3. **The order page.** New state for `awaiting_quote`: "We're confirming your delivery price" with the items total, the store area and "We'll email you the final price"; it polls like the pending state and switches by itself to the Pay state when quoted. The Pay state shows **items, delivery fee and the final total**. `expired` from `awaiting_quote` reads "We couldn't confirm delivery in time — nothing was charged" + "Put these back in my bag". Remove the web app's `sendOrderCreatedEmail` and its call in `submitOrderAction` (the core now sends the "confirming" email).
4. **Admin "Send price".** In the admin order view (`engine/packages/cms/src/admin/orders/`, the owner and store panels), for an `awaiting_quote` order: a rupiah input (integer, ≥ 0, `0` = free) and **Send price**, posting to `/api/x/orders/quote` (mount the core's handler there; auth as the core's handler says). Show the deadline ("quote by 14:30") and, once quoted, the fee and the new total. Also a **WhatsApp** button (click-to-chat `wa.me/<buyer whatsapp>?text=…`) prefilled with the order number and the order link — the admin view gets the link through a server call that opens `trackingTokenEnc` (core's `openToken`), never stored in the page beyond the button.
5. **Tests.** Update `gate.spec.ts`: buyer checks out (no fee shown) → order page "confirming" → a staff step quotes (Local API `quoteDeliveryFee` in the gate's `payload run` helper, `GATE_DB=local`) → the page shows the fee and total by itself → Pay → Settle → paid. The abandoned case covers both windows. `payment.spec.ts`: seed orders quoted. Unit tests for the admin input's validation and the WhatsApp link builder.
