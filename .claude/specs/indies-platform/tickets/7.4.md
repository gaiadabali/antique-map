## The spec — `tests/e2e/shop-fulfilment/flow.spec.ts`, at 390 px
1. **Guest buys** two in-stock products → pin in Bali → fee + total from the server → simulator payment → the order page; capture the tracking link (from the order page or the email when `MAILPIT_URL` is set).
2. **The nearest store fulfils**: log in as that store's user; the paid order is on top; processing → waiting for driver → upload a driver image → on the way → delivered. Time it.
3. **The buyer tracks**: the tracking page shows each step with times, the driver image (only after upload), the store's name and WhatsApp.
4. **Another store's user** sees no such order (an empty list or a refusal — assert it).
5. **The owner reassigns a second order** (buy a second one, then as the owner move it to another store with stock; assert the stores changed and the panel shows it).
6. Screenshots at each step into `docs/gates/shop/`.

Configuration, all by environment, none hard-coded: `E2E_BASE_URL` (default the local shop host + port), `E2E_OWNER_EMAIL`/`E2E_OWNER_PASSWORD`, `E2E_STORE_A_EMAIL`/`_PASSWORD` (the nearest store's user), `E2E_STORE_B_EMAIL`/`_PASSWORD` (another store's user), `E2E_PIN` (lat,lng; default -8.6705,115.2126), `MAILPIT_URL`. **Locally** (`GATE_DB=local`) the spec creates those users and their stores' stock itself through the fixtures, as `store-panel-fixtures.ts` does; against staging it creates nothing and only uses the accounts given. Never print a password; never write one to a file.
