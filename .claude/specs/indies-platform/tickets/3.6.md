## What to build
1. **Language (3.6.a).** Every collection, global, field label, description and validation message has `en` and
   `id`. Write `engine/packages/cms/src/i18n/labels.test.ts` that walks every registered collection and global
   (recursively through groups, arrays, tabs, rows) and fails on any `label`/`description`/`labels` that is a plain
   string or lacks `en` or `id`. Fix every gap it finds (labels only). The user's language follows `users.language`
   when set (Payload's `i18n.fallbackLanguage` en; the profile's language switch is Payload's own preference — make
   sure it is visible).
2. **Sidebar by task (3.6.b).** `admin.group` with bilingual names: **Antiques** (works, makers, places, terms,
   media, masters), **Shop** (products, discounts), **Stores and stock** (stores, stock-levels), **Orders**
   (orders, payment-events), **Leads and partners** (leads, partners, chat-sessions), **Content** (pages,
   redirects), **Settings** (site-settings, users, events). `admin.hidden` hides a collection from a role that cannot
   read it (store users see only Orders and Stores and stock; editors do not see Leads and partners, Settings'
   site-settings or events) — use the same role helpers as the access functions so menu and access agree. Access
   still enforces it; this is only the menu.
3. **Dashboard shell (3.6.c).** A custom dashboard view (`admin.components.views.dashboard` or Payload 3.90's
   equivalent — check the docs) with two panels: "Orders to act on" (count of orders in `paid` or
   `needsAttention`, scoped to the user's store for store users) and "New leads" (count of leads with status `new`,
   owner only; hidden for others). Counts come from a server component using the Local API **with
   `overrideAccess: false` and `user: req.user`** so each role sees its own numbers. Bilingual labels.
4. Keep `pnpm verify` green; regenerate the import map (`pnpm --filter @engine/cms generate:importmap`).
