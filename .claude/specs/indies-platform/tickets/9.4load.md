## Why
9.4.a's builder (`engine/packages/migrate/src/redirects/{build,cli,normalise,rules}.ts`) writes
`redirects.<site>.json` and `unresolved.<site>.json` from a **works fixture**; nothing writes `redirects` rows into a
database. On staging (44 published works) every legacy URL answers 404, so 9.4.c cannot pass.

## What to build
1. `works-from-db.ts`: reads every work's `legacyId`, `published` state and public path from the database via the
   Local API (read-only, `select` only those fields) into the builder's `WorkLookup[]`.
2. `load.ts`: runs `dedupeLegacyUrls` + `buildRedirects` for a site with those works, then **upserts** the rows into
   `redirects` keyed on `from` (create new, update changed, leave identical untouched) and deletes rows of that site
   whose `from` is no longer produced **only with `--prune`**. One transaction per batch of 500. Idempotent: a second
   run reports 0 created, 0 updated. Refuses a chain or loop (the builder throws — keep that).
3. `load-cli.ts`: `--site gallery|shop|all`, `--dry-run` (counts only, no writes), `--prune`, `--unresolved-out <dir>`
   (writes `unresolved.<site>.json` for the 9.4.c tool's `--unresolved`). Prints counts: rows, gone, unresolved,
   created, updated, unchanged, pruned. Never prints connection strings.

## Tests (by name)
"loads rows for published works and gone rows for retired addresses"; "a second run changes nothing"; "a dry run
writes nothing"; "prune removes only rows of that site that are no longer produced"; "an unpublished work's old URL

`--maxWorkers=1`, seeding works through the Local API.
