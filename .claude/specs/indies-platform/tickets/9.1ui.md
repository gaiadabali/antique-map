## What to build
1. **The inbox** — a custom admin view at `/admin/leads` (owner only; an editor or store user gets Payload's
   unauthorised state, never data): a list of leads, newest first, **defaulting to status New**, filterable by
   **site**, **kind** and **status** (links/selects that set search params — server-rendered, no client state
   needed), each row showing kind, site, status, the person's name, the channel they prefer, age ("3 h ago") and
   the first line of the message (truncated, text only). Each row opens Payload's own edit view of the lead.
   Paginate (25 a page). Counts per status in the filter bar. The nav: add a link to the inbox in the
   **Leads and partners** group (Payload `admin.components.afterNavLinks` or the view's `nav` — whichever 3.90
   supports cleanly) — owner only.
2. **The lead's edit view** works the lead: `status` and `notes` already edit there; add to the sidebar a
   **"Open the source"** block (a UI field component) linking the lead's `items` (works or products, to their
   admin edit pages and their public pages) and its `chatSession` (to its admin page); and on a `partnership`
   lead with no `partner` yet, a **"Create partner"** button that creates a `partners` row (business name from
   the lead's name, contact person/WhatsApp/email copied, `site: 'shop'`, status `prospect`) with the acting
   user (`overrideAccess: false`), sets `lead.partner`, and navigates to the new partner. Closing a lead: the
   admin description of `notes` says "one-line outcome when you close".
3. **Partners** — the list's default columns (name, kind, status, products carried count, updatedAt); the
   `productsCarried` picker shows product name and SKU and offers only published products (`filterOptions`);
   the partner's sidebar lists the leads that point to it (a join field is a schema change — use a UI field that
   queries `leads` where `partner = id` instead). Make sure no `auth` is on `partners` and no login route exists
   for partners (a test asserts the collection has no `auth`).
4. **The "new lead" email** is 9.1core's `notifyNewLead`; nothing to build here — check the inbox link it
   sends (`/admin/collections/leads/{id}`) opens the lead.

All copy `{ en, id }` beside the code (3.6 pattern), the admin's own look, no raw colours or font families.
