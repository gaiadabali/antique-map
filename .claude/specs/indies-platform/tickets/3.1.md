   spec (uig:4030:ig_db, uoei:4031:oei_db — `lib/sites.sh`) to DEPLOYMENT.md §2's one-site shape: site user
   and pm2 process `uindies`, port 4030 on 127.0.0.1 only, database `indies_db` with role `indies` (LOGIN
   only, `CONNECTION LIMIT 20`), nginx `server_name` on **both** staging hostnames so the `Host` header
   passes through, the `/_media/` location on the shop's canonical host serving the bucket anonymously
   (GET/HEAD, authorisation and cookies stripped) — the vhost through CloudPanel's editor, never a file
   edit. One media bucket `indies-media`; `archive-masters` stays private and versioned. The env file gains
   DEPLOYMENT.md §8's shape: `GALLERY_HOSTS`, `SHOP_HOSTS`, `ADMIN_HOST` (the shop's canonical host),
   `RUN_MIGRATIONS=1`, `HOSTNAME=localhost`, `PORT=4030`, `MEDIA_PUBLIC_URL` at `/_media/` on the shop's
   canonical host, one S3 key pair for both buckets. A production run stays refused unless both specs are
   passed explicitly with a bucket suffix (keep that rule). The script stays idempotent with
   `--dry-run`, `--report`, `--verify-restart`, and `scripts/ops/test/` stays green.
2. **8.5's RustFS parity findings folded in** (CARRY-OVER.md §3 step 8: do not merge 8.5's per-brand plan
   files — fold its findings). The public-GET policy is scoped by prefix — anonymous GET only under
   `derivatives/` and `iiif/` (the slash included), never the whole bucket — and anonymous listing is
   denied on both buckets. The app's one key reads and writes both buckets and never deletes under
   `masters/`; policies are data applied by `@engine/media`'s `storage:policies` plan, bucket policies

6. **The release, by hand over SSH — never a push.** Replicate `.github/workflows/release.yml`'s build
