## Build
1. `geo.ts` — haversine km; `isInIndonesia(lat,lng)` (lat −11.5…6.5, lng 94.5…141.5); pin validation.
2. `pick-store.ts` — `pickStore(db, { lines, pin }) → { storeId, distanceKm } | { refusal: 'no_single_store' |
   'outside_reach' | 'outside_indonesia', missing?: {productId, variantSku}[] }`: nearest **active** store by
   straight-line distance holding every line in full (variant-aware), ties broken by store code; beyond the last
   delivery band → `outside_reach`.
3. `create-order.ts` — **one transaction** (READ COMMITTED, `SET LOCAL lock_timeout = '5s'`): re-parse the bag
   cookie and re-price via 6.2; re-check the welcome code with the contact; pick the store inside the transaction;
   for each line ordered by (product_id, variant_sku):
   `UPDATE stock_levels SET quantity = quantity - $n WHERE store_id=$s AND product_id=$p AND variant_sku IS NOT
   DISTINCT FROM $v AND quantity >= $n RETURNING id` — zero rows → roll back everything, refusal `out_of_stock`
   naming the line; insert the order in `pending_payment` with priced lines and totals exactly as quoted (integer
   rupiah), `expiresAt` = now + site-settings `orderExpiryMinutes` (default 60), the order number (`orders_number_seq`
   if it exists, else the collection's rule), a tracking token = 32 random bytes base64url returned once, only its
   sha256 hex stored in `tracking_token_hash`; increment `discounts.used_count` for a used code in the same
   transaction. Return `{ orderId, number, trackingToken, totals }` or a refusal. Contact and address validated
   server-side, Indonesia only.
4. `index.ts` exports with exact types and a header documenting the call order.
