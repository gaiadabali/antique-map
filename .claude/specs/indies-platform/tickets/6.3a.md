## Build, in this order (commit after each)
1. **Checkout page** `checkout/page.tsx`: an empty or missing bag redirects to the bag. A server-rendered review of the lines and the server's totals (from `quoteBag`; never a client price). Form fields per `CheckoutDetailsInput` (name, WhatsApp, email, address text, notes, and the pin's `lat`/`lng` as hidden fields set by the picker). Submit is a **server action** in `server/shop/checkout/submit.ts` calling `createOrder` with the raw bag cookie, the form details, the bag's welcome code and `expectedTotalIdr` = the total the page showed. Success → `redirect` to `/order/{number}?t={trackingToken}` (6.5 builds that page; a 404 there is expected for now). Refusal → re-render with a plain message per kind from the lexicon: `invalid_details` names the fields; `price_changed` shows the new total and asks to confirm again; no single store / out of stock tells the buyer **before paying**, with a WhatsApp handoff; `outside_indonesia` says Indonesia only.
2. **Map pin picker** `sites/shop/checkout/pin-picker.tsx` (`'use client'`) inside `MapPinShell`. With a browser Maps key (`GOOGLE_MAPS_BROWSER_KEY`, read on the server and passed as a prop; **never** hard-coded) load the Maps JavaScript API by script tag, with Places autocomplete and a draggable pin. **Without a key** (the local and CI case) the fallback must fully work: paste a Google Maps link **or** type lat/lng, parsed for preview and **validated again on the server**. Default centre: Denpasar.
3. **`/api/x/geocode`** `route.ts` (POST `{lat,lng}` or `{link}`): parse a pasted Maps link (`@lat,lng`, `?q=lat,lng`, `/place/…/@lat,lng`), validate with `isValidPin` and the Indonesia bounds, and — only when `GOOGLE_MAPS_SERVER_KEY` is set — reverse-geocode for a display address; without the key return the pin with `address: null`. Rate-limit per IP the way `/api/x/collect` does. Tests in `geocode.test.ts`: "parses the three link shapes"; "a pin outside Indonesia is refused"; "garbage input is a 400 with a plain message"; "no key → no outbound call".
4. **Fee preview**: when the pin changes, the page shows the delivery fee and total **from the server** (a server action calling `quoteBag` with the pin). The client never computes a fee.
5. Board: `pnpm tasks:report 6.3.a` when steps 1–4 are evidenced. Never tick 6.3.d.

## Rules that hold
Money is integer rupiah priced on the server; a price or quantity in the request is never read. Links `prefetch={false}`; the checkout and every read that decides a purchase is uncached (per ARCHITECTURE §Rendering). Tokens and shared components only, copy in the lexicon, no file over 300 lines. Keys only from env, never logged.
