# 0.5 ARC-D — senior-db review (2026-09-28)

Branch `worktree-agent-a5abd4af956ac043a` @ 0591e73. Reviewer: senior-db. Read-only; claims tested on a throwaway `postgres:18` (18.6).

## Verdict: SIGN-OFF WITH FIXES

The design holds: one writer, a scalar `target_key` under a partial unique index, a guarded `UPDATE` for counted stock, lazy expiry inside `reserve()`, dedupe inside the applying transaction. The promise "reserve() never aborts the caller's tx" holds only under conditions the contract does not yet state. Three blockers are contract text, not redesign.

## Evidence (PG 18.6)

Index `UNIQUE (target_key) WHERE exclusive AND status IN ('active','converted')`; insert `ON CONFLICT (target_key) WHERE <same predicate> DO NOTHING RETURNING id`.

1. READ COMMITTED, same target concurrently: T2 waits, gets `INSERT 0 0`, no error.
2. REPEATABLE READ, same race: `could not serialize access due to concurrent update` — T2 aborted.
3. Two bags in opposite order, READ COMMITTED: `deadlock detected` — T1 aborted.
4. Lapsed row, two concurrent reserves: one `expired` + one `active`. Lazy expiry is safe.
5. As 3 with a savepoint: recoverable, but each buyer keeps half a bag and pays `deadlock_timeout`.

Strategy to freeze: `INSERT … ON CONFLICT … DO NOTHING RETURNING` under READ COMMITTED, targets reserved in a fixed order. No advisory locks. `SELECT … FOR UPDATE` for operations on existing rows. Savepoint only as fallback.

## DDL the SCH lane will need (follow-up)

All via `afterSchemaInit` / `extendTable`, so migrations and dev push both carry it.

- **reservations**: scalar FKs (`product_id`, `unit_id`, `variant_id`, `location_id`, `cart_id`, `order_id`, `customer_id`, `hold_request_id`, `offer_id`, `invoice_id`, `granted_by`) — no polymorphic `_rels`; `target_key text NOT NULL`, `exclusive boolean NOT NULL`; `status` CHECK (5 values); `quantity int CHECK (> 0)`, `CHECK (NOT exclusive OR quantity = 1)`; CHECK tying `target_key`/`exclusive` to FK columns; `expires_at timestamptz NOT NULL`; **`UNIQUE INDEX (target_key) WHERE exclusive AND status IN ('active','converted')`** non-deferrable (reserve()'s `ON CONFLICT … WHERE` repeats the predicate verbatim); `INDEX (expires_at) WHERE status='active'`; `INDEX (order_id)`; `expiring_notified_at timestamptz`. Collection: drafts/versions off, create/update/delete access `false`; staff actions via service endpoints.
- **stock_levels**: `UNIQUE (variant_id, location_id)`, `CHECK (on_hand >= 0)`, `CHECK (reserved >= 0)`.
- **payment_attempts**: `UNIQUE (provider, provider_ref)`, `INDEX (order_id)`, `INDEX (status, expected_by) WHERE status IN ('created','pending','requires_action','authorised')`.
- **payment_events**: `UNIQUE (provider, provider_event_id)` + `attempt_id`, `outcome`, payload hash; separate unmatched-events table.
- **payment_refunds**: `UNIQUE (attempt_id, refund_ref)`.
- **engine.domain_events**: uuid PK, `INDEX (occurred_at, id) WHERE dispatched_at IS NULL`; dispatcher `FOR UPDATE SKIP LOCKED`; per-consumer dedupe PK `(consumer, event_id)`.
- **idempotency_keys**: PK `(scope, key)` + stored response, `ON CONFLICT DO NOTHING` inside the request tx.
- **Money**: `bigint` + CHECK `0..2^53−1`, currency `char(3)`; FX rate/buffer `numeric` read as text; `ExactRatio` as text; rounding records as rows or jsonb beside the figure.
