Reviewed `feat/p4-web` at 8b78826 (one commit on e4da692) in `antique-map-p4-web`. I rebuilt both apps from the commit with `BRAND`, `BRAND_ROOT`, `DATABASE_URL` and `PAYLOAD_SECRET` unset, using Turbopack: 55 s and 45 s, both green. No brand string appears anywhere in `.next/server` or `.next/static`, and every prerendered shell is 0 bytes. I served the builds with `next start` on 4206–4208, and the gallery standalone `server.js` on 4209. vitest over `http` and both apps passes 14 files and 151 tests. Typecheck, eslint, file size, brand literals, client-safe and `check:routes` (41 routes) are all ok. `check.mjs` re-ran green on 4206. I checked `/admin/login` renders on all four brand/storefront pairs; I did not repeat the sign-in.

**Verdict: sign off with should-fix.** Cache Components is confirmed. `instant = false` plus `htmlLimitedBots: /.*/` is the only lever 16.3.6 offers, and it does not cost streaming (#1). Two findings belong before the merge or in its fix pass. #2 is cheap and guards everything built on #1. #3 is a public disk-write that 5.1 would deploy. #4–#8 need decisions or doc lines before phases 11/22/33 copy the pattern.

This branch does **not** meet 4.1.b's or 4.1.g's health clause: `/api/health` answers 503 `not-wired` on every host. The tarball clause is not evidenced here either. Neither is a code defect, but 4.1 cannot be ticked until the `@engine/http` → `payload`/`@engine/cms` dependency is approved. Approve it: every DOM handler will need it too.

## Findings

1. **no action: the model is right; its cost gets a note** — `apps/*/next.config.ts:36`, `(site)/[locale]/layout.tsx:30`. `instant = false` is the documented escape hatch for a blocking root layout (`route-segment-config/instant.md`: "Setting `false` on the root layout disables static shell validation"). Variant D shows the build fails without it. A `<Suspense>` around `{children}` would flush 200 before the page decides, so rejecting it was correct.

   `htmlLimitedBots: /.*/` is the only way 16.3.6 bypasses a PPR shell's stored status. Variant A answers 200 for a `notFound()`, and `shouldForceDynamicPPRRender` is the only path around it. No supported route-level alternative exists: `dynamic` is gone, and the proxy cannot see the database.

   What it costs, measured:
   - (a) The body still streams.
   - (b) The static shell is never served. That is free today, since every shell is empty, but it rules out prerendered or ISR pages for good.
   - (c) Every `generateMetadata` now gates the first byte for every visitor. It must stay on cached reads only, which the item route does.
   - (d) Every prefetch is a full dynamic render (#4).
   - (e) The nonce CSP (#9) depends on it too. The CSP guide says "PPR is incompatible with nonce-based CSP", and it holds only because no shell is served.

   The docs promise only "blocking metadata". The shell bypass is an implementation consequence (the comment at `app-page-runtime.js:340-342`), so it can change in a minor release. Hence #2. Record (b)–(e) in ARCHITECTURE §9 beside the setting.

2. **should-fix (this branch)** — the only guard on #1 is `src/spike/check.mjs`. It is manual, not in CI, and it is deleted with the spike in phase 33, together with the route's canonical rule (`spike/id-slug.ts`, `item/[idSlug]/page.tsx:45-57`). A Next bump that changes the bot path would silently turn every 404 and 308 into a 200 soft-404.

   Evidence: nothing under `test:e2e` or CI requests a page for its status. `check:routes` checks files, not answers.

   Fix: a Playwright e2e in the existing job, against the production build, with a normal UA. Assert:
   - `/nope` and `/<prefix>/not-found`: 404
   - `/product/<id>-stale`: 308 with a once-encoded `Location` that then answers 200
   - `/product/<id>-b%61li`: 308
   - an unsupported locale prefix: 404
   - a no-UA request (after #5 lands): 404

   Move `parsePublicId` and a `canonicalOrRedirect(publicPath, canonical)` helper out of `spike/` into `src/item/`, with `test/id-slug.test.ts`, so phase 33 inherits them rather than deleting them.

3. **should-fix (before 5.1)** — two problems, both reachable on the public internet once 5.1 deploys.
   - **The spike is live on every brand and writes to disk for anyone.** `item/[idSlug]/page.tsx` and `spike/actions.ts:31-58` are not gated. Only the two controls check `SPIKE_CONTROLS` (`actions.ts:62,72`). So Indies Gallery serves the fixture "Café de Java" at `/product/1706-…`, and any anonymous POST adds a never-pruned entry to `os.tmpdir()/indies-spike-<PORT>.json` and rewrites the whole file (`store.ts:36-42`, `form-result.ts:17-30`). An entry is dropped only when it is shown (`form-result.ts:37-41`). That is O(n²) disk I/O on Helios, whose disk hit 93%. Evidence: 300 posts to :4207 kept 300 results. Fix: `notFound()` in the item route and a refusal in every spike action unless `SPIKE=1`, which the boot check refuses in production. Alternatively, prune entries older than ten minutes on each write and cap the map.
   - **`withPayload()` puts `Critical-CH: Sec-CH-Prefers-Color-Scheme` on every storefront page** (`routes-manifest.json:29`, source `/:path*`). Chromium restarts the navigation when a critical hint was not sent, so **every first visit renders the page twice**. Evidence: 2 document requests on a fresh context for 4206 and 4208 `/`, at both widths. Lighthouse CI always runs as a first visit, so it sees the doubled TTFB as well. senior-be #11 found the `Vary` split on assets; this is the latency half.

     Fix: in each `next.config.ts`, rewrite the entry that `withPayload` adds to `source: '/admin/:path*'`. For example:

     ```ts
     const headers = config.headers
     config.headers = async () =>
       (await headers()).map((h) => (h.source === '/:path*' ? { ...h, source: '/admin/:path*' } : h))
     ```

     Then assert that `/` has no `Critical-CH` header.

4. **should-fix (C13 decision, before 11.x and 22)** — a render consumes a post's result.
   - **`takeFormResult()` deletes the result during render** (`form-result.ts:33-43`), and under #1 a router prefetch is a full render. Evidence (`rv/prefetch-eats-result.mjs`): post ship-to (303); a `<Link>`-style prefetch of the same page returns the result; the visitor's GET then shows none. A reload, a second tab, or a link-preview fetch that carries cookies does the same.
   - **Fix, architect's call on C13 `FORM_RESULT`:** keep the opaque id in the 303's `Location` (`?r=<id>`) and let the entry live out its ten minutes, so a render reads it without deleting it. Failing that, never take a result on a request that has `RSC` or `Next-Router-Prefetch`.
   - **Add to CONVENTIONS §6:** storefront links are `<a>` or `<Link prefetch={false}>`. A prefetch under `htmlLimitedBots` costs a full render with the page's database reads, so a 48-card grid in view means 48 renders.

5. **should-fix (docs)** — the no-UA gap is wider than the write-up says. `cache-components.md:79` claims "200 + meta refresh" for a request with no `User-Agent`. I measured 200 with no refresh: the redirect exists only in the flight data, so without JS it never happens. `/xyz` and `/product/9999-x` are also 200. The fix proposed below is still right; correct the row.

6. **should-fix (docs, ARC)** — the spike breaks a rule it does not list. `CONVENTIONS.md:246` and `AGENTS.md:37` say anything reading cookies, headers, the ship-to market or availability "sits inside `<Suspense>`, so the cached shell streams first".

   The spike's page reads `shipTo`, the bag, the result cookie and `x-public-path` outside `<Suspense>` (`page.tsx:54,66-72`). It must, because a JS-off visitor needs the form's current value and the result in the first flush. There is also no cached shell left to stream first (#1).

   Add item 6 to the spike's "For ARC" list. Rewrite the rule as: runtime reads that the first flush must carry (forms, their current values, a post's result, the canonical check) run in the page body. Slow or live reads (availability, live price, cart totals) run inside `<Suspense>`, and a streamed part carries no form.

7. **should-fix** — availability is fetched in the page body, not only in the panel. `page.tsx:71` awaits `getAvailability()` in the body's `Promise.all` for `SpikeControls`, even when the controls are off. The first flush therefore waits on the availability read, and after a sale (`expire: 0`) it waits for the refill. The panel still streams, but `liveLatency()` (`purchase-panel.tsx:18-21`) delays only the panel, so the "only the panel streams" measurement never exercised this. Phase 33 will copy the page. Fix: read availability for the controls only when `SPIKE_CONTROLS === '1'`, or render the controls inside the same `<Suspense>`.

8. **should-fix (docs decision)** — availability sits in a shared cache that has no expiry backstop. `reads.ts:45-50` caches availability with `'use cache'` + `cacheLife('max')`, and correctness rests on every writer calling `revalidateTag(…, { expire: 0 })` in the same process. ARCHITECTURE §9:350 says availability "never enter[s] a shared cache"; its next bullet tags availability for `{ expire: 0 }`. The spike picked the second. That works with one in-memory handler per brand and every writer invalidating. One missed writer, for example a sweep, a webhook or a `jobs:run` worker without `invalidate()`, serves a sold map as available until restart. `reserve()` still refuses the sale, so the harm is a false "available", not money. Fix: ARC settles one sentence. I recommend a short `cacheLife` backstop (`{ stale: 0, revalidate: 30, expire: 60 }`) on top of the tag.

9. **agree (CSP)** — per-request nonces. The docs confirm Next takes the nonce from the request's CSP (`content-security-policy.md:181`). The flight scripts carry per-request data, so hashes cannot hold. SRI (`experimental.sri`) covers only build-time files, never inline scripts, so it is no alternative; add that line to §7. Two notes for 41.1.a:
   - The nonce holds only while #1's full render holds, so pin it with #2's e2e plus one CSP check (0 violations on an item page).
   - The static `/_not-found` (○) carries no nonce. It is reachable only for `/_next/*` misses, so this is harmless.

10. **nit** — `item/[idSlug]/page.tsx:54-55`: a missing `x-public-path` compares `null !== canonical` and redirects the canonical URL to itself, a loop if the proxy is ever bypassed. Redirect only when the header is present and different; otherwise throw. A redirect also drops the query (`/product/1706-old?utm_source=x` → no query). Decide whether to keep it (`permanentRedirect(canonical + search)`); MIGRATION §6 is silent. `resolve()` runs twice per request (metadata and page), so wrap it in React `cache()`.

11. **nit** — the shell and its loaders.
    - `load-shell.ts:66-73`: `brandIcons()` detects a missing file by `url.includes('?')` and hard-codes `apple-touch-icon.png` and `site.webmanifest`. Take the names from C13 `ROOT_REWRITES` or C1, and return `null` from a resolver instead.
    - Each render calls `brandAssetUrl()` about 8 times, twice over (the layout's metadata and its body), and each call does 3–4 sync fs syscalls. Memoise per process, since the file changes only with a deploy, which restarts the process (`version.ts:8-10`).
    - `shell/*`, `styles/*`, the `(site)` layout, page and not-found are byte-identical in both apps (`diff -q`). Fine for a placeholder, but 11.3/22 should move `brand.ts`, `links.ts` and `messages.ts` into a shared package before they drift.

12. **nit (follow-up, C10)** — the item exception misses undecodable slugs. `%FF`, a Latin-1 `caf%E9` and a raw UTF-8 request line are 404 from the proxy (`x-middleware-rewrite: /en/not-found`). C10's exception returns 308 by id for every other odd slug. MIGRATION §6's "whatever its slug spells" should include these; the URL gate (37.1.b) will find any in the inventory.

13. **nit** — `health/route.ts:15-17`, `legacy/route.ts:11`, `legacy/unbuilt/route.ts:15` use `void request.headers.get('host')` to force request time. It is documented ("request object properties … stop prerendering"), but `await connection()` states the intent. Put either in one `atRequestTime()` helper.

14. **nit** — spike accessibility, since phase 33 will copy it.
    - Every bag line's button is just "Remove" (`forms.tsx:67`). Name the line, e.g. `aria-describedby` pointing at the title, or visually hidden text.
    - `role="status"` on a result present at load is never announced (`page.tsx:85`). Move focus to it, or render the live region empty first.
    - The placeholder's `aria-busy` region has no live politeness, so the swapped panel is silent. Give the `<section>` `aria-live="polite"`.

    The shells themselves are good: a skip link, `:focus-visible`, 44 px targets, `lang`/`hrefLang` on locale links, and a label-in-name brand link.

15. **nit (docs)** — `cache-components.md:28` says the only prerendered routes are `/_not-found` and the admin. `next build` also marks `/[locale]/item/[idSlug]` and `/[locale]/[...missing]` as ◐, each with an empty shell. Also, `actions.ts:26` tests the root-relative regex on the raw `returnTo` while redirecting to the WHATWG-normalised `url.pathname`; `/\t/evil.com` normalises to `//evil.com`. `parsePublicPath` refuses it today, so it is safe (measured), but test `url.pathname` too.

16. **follow-up (HAR)** — placeholder mounts vs route parity. The approach is right for now: 34 mounts per app re-export `@engine/http/legacy/unbuilt` with the owning lane in a comment, and methods match C13, so parity passes. What parity cannot see is a lane that lands `@engine/http/<area>` and repoints one app but not the other; that app keeps a 404 and CI stays green. Fix (tooling): `check:routes` fails when a mount's re-export specifier is neither `@engine/http/<handlerOf(path)>` nor the placeholder, and fails when that handler's module exists while a mount still names the placeholder. Rename the placeholder `@engine/http/unbuilt` when ownership allows; it is not legacy. senior-be #2 covers `robots`.

No Client Component receives money, dates or dimensions. The only one is `JsIndicator`, which takes two strings. Every link is built by `href()` on the server. No hydration hazard found: `computedAt` renders on the server only.

## Proposed contract changes

- **C2 `ShellVM.assets.touchIcon` / `assets.manifest`: agree.** Both are `string | null`, versioned by `brandAssetUrl()`, and `null` when the brand ships no such file. Loaders build them in 11.3, and `brandIcons()` goes away (#11).
- **C13: the proxy sets `user-agent` when it is missing: agree.** It must be non-empty, because Next treats `''` as "no UA" (`app-page-runtime.js:339`). Use a recognisable token such as `indies-proxy (no user-agent)`, so analytics and rate limits can tell it apart. Test it in #2's e2e.
- **Also:** the one-308 wording in MIGRATION §6, TASKS 4.1.e and 37.1.b. `permanentRedirect()` answers 308 in a Server Component, the only place the id lookup can live. Search engines treat 308 as permanent. Amend the docs and the URL gate to "one permanent redirect (301 or 308)".
- **Also:** the lower-case escape wording in MIGRATION §6 and C10. Next upper-cases `%c3%a9` before the proxy, and RFC 3986 makes the two spellings one URI, so this is not a second address. Drop it from the must-redirect list.

## "Found" — DESIGN-SYSTEM §2 NotFound

**Confirmed, and it is Next's behaviour, not the spike's settings.** In the minimal 16.3.6 app, a `notFound()` in a page ships `<html id="__next_error__">` with an empty `<body>` in three cases: no Cache Components and a sync layout (E), no Cache Components with a blocking layout (C), and the spike's configuration (B). The designed page is built client-side from the flight data. The fallback document also has no `lang`.

Crawlers get the 404 and `noindex`. A visitor without JavaScript gets a blank page.

It needs a UXE/ARC decision before phase 22. One option: the proxy rewrites its own not-founds (unknown paths, closed modules, internal paths), which are most of them, to an engine route handler that answers the designed 404 as server-rendered HTML with status 404. Item-level misses keep Next's `notFound()` and accept a client-rendered body. The other option is to accept the blank page without JS and say so in DESIGN-SYSTEM §2.
