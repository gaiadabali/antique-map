## What was already there, and what this ticket changed

Much of 3.2's ground was laid by 8.2 (the works collection, its publish guard, the uid hook).
The ticket's deltas, implemented here:

- **3.2.a — references replace sources.** `works.references` is now a plain-text array of
  `{citation: text (required, <=300, whitespace refused), note: textarea (localized, <=600)}` —
  `fields-object.ts`. The `sources` collection folder is deleted and its registry line removed.
  Its vocabulary db test's source cases are gone; its table count now expects 4
  (`makers`, `places`, `terms`, `_places_v`).
- **3.2.b — `works.publicId`.** Integer, unique, indexed; `public-id.ts` assigns it on create
  under the works advisory lock (`SELECT coalesce(max(public_id),0)`) with
  `nextPublicId()` (`work-record.ts`): floor 100000, never below, refuses a nonsense current max.
  Any change on update is refused ("keeps its public id for ever"). A **script create — local API,
  no user — may hand an id >= 1**, which is how the migration importer keeps the old site's number
  (tested with 4211).
- **3.2.c — AI drafts and the bilingual guard.** `cataloguing.aiDraft` is now a group with one
  `{drafted, verifiedBy -> users, verifiedAt}` entry per draftable field
  (title, description, objectType, date, places, subjects, dimensions) — `fields-staff.ts`.
  `unverifiedAiDraft()` (vocabulary.ts) feeds `work-guard.ts` and `work-cataloguing.ts`; a
  drafted-but-unverified field blocks publishing, and a verified one (`verifiedAt` set) does not.
  `work-publish.ts`'s refusals are bilingual — an English sentence plus an Indonesian one — and
  name the missing field: title, object type, date precision, places/makers, grade, and the AI
  problem ("AI membuat draf ... belum ada yang memeriksanya").
- **3.2.d — status, location, askingPrice.** `works.status` select
  (`available|on-hold|sold`, default `available`, indexed) and `works.location`
  (`singapore|jakarta`, **no default and never blocking publish** — requirement 16.8) on a record
  row. `works.askingPrice` is a number field validated to whole US dollars (0 or more), with
  field-level access read/update/create owner-only (`OWNER_ONLY_ACCESS`), sidebar placement,
  cleared on duplicate. Tests: owner reads 18000; editor's and public's reads lack the property;
  18000.5 refused.
- **3.2.e — media subject and file access.** `media.subject` is a required select
  (`work|product|store|other`), frozen at intake with `role` and `provenance`; it disambiguates
  CONTENT-MODEL section 5's role table. `media` read for store users is now a `Where`
  (`subject: { not_equals: 'work' }`) — enforced in access, not the UI. The full-resolution file
  (`isReadingStaticFile`) is the owner's and the editors' alone — store users get 403.
  **TODO(2.2-merge):** `engine/packages/config` does not export `SITES` on this branch, so
  `work-record.ts` keeps its uid constants with a `// TODO(2.2-merge): read SITES.gallery.works`
  comment, as the ticket directs.

## Tests (all named in the ticket)

- `works.db.test.ts`: publicId sequencing (from >=100000, +1 per work, kept for ever, script
  hands the old id); five `refuses publishing a work missing <field>` cases (title, object type,
  date precision, primary image with a person-checked alt — via an `altSource: 'ai-draft'` media
  row, since a blank alt cannot even be created — and grade); `refuses publishing while a
  drafted field is unverified` plus the verified counterpart; the incomplete-publish case still
  lists every reason at once.
- `works-price.db.test.ts` (new; split out to keep `works.db.test.ts` under 300 lines):
  `askingPrice is absent from the public read` / `from an editor's read` / `the owner reads
  askingPrice` (owner records it over the Local API, reads over REST per role) and an editor's
  whole-USD validation; `lets an editor publish a complete work`.
- `works.test.ts`: `nextPublicId` table (null/0/99 999 -> 100000; 100000 -> 100001; -1/1.5 throw);
  aiDraft per-entry shape; status default and location's absent default; askingPrice access
  across read/update/create for null, customer, editor and store.
- `places/vocabulary.db.test.ts`: `a place cannot be its own ancestor — directly or two levels
  down — published or as a draft` (renamed to the ticket's wording; the direct self-parent and
  the Kota Tua > Jakarta > Java cycle are both asserted), and the table count now 4.
- `media` tests: subject required at intake and frozen; store user 404s a work-subject record but
  reads a product-subject one; full-resolution file 200 for owner/editor, 403 for store;
  `media.test.ts` unit tests updated for the new file rule.
